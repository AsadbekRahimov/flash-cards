## 1. Зачем

- **Ученики хотят говорить.** Продукт учит узнавать слова, а цель учеников — заговорить и сдать экзамен: IELTS, SAT, школа (цели онбординга). Speaking тренировать не с кем.
- **Pro сейчас — «больше того же».** В него входят безлимит новых слов, заморозка серии, spelling и gap-fill, симулятор словаря. Бесплатных 20 новых слов в день большинству, вероятно, хватает, поэтому пейвол видят редко. Проверить по событию `paywall.shown`.
- **Голосовое боту сейчас остаётся без ответа:** `LearnerDmHandler` реагирует только на текст. А голосовые — самый привычный жест в Telegram в регионе.

**Идея.** Ученик разговаривает с ИИ-собеседником голосовыми сообщениями прямо в чате бота. Собеседник отвечает голосом, задаёт следующий вопрос и поправляет ошибки. После разговора — разбор, а слова, которых не хватило, можно одной кнопкой добавить в свои карточки.

**Цели пилота** — гипотезы, проверяются A/B-группой:

| Метрика | Цель |
|---|---|
| Удержание D7 | +5 п. п. к контрольной группе |
| Конверсия Free → Pro | ×1,5–2 к контрольной группе |
| Расходы на ИИ | ≤ 15 % выручки Pro |
| Задержка «голосовое → ответ» | p95 ≤ 8 с |
| Ответ голосом на напоминание-вопрос | измерить базу на пилоте, цель — больше половины |

## 2. Сценарий ученика

### 2.1. Первый разговор

Сразу после онбординга бот задаёт вопрос голосом: «What's your name and where are you from?». Текст вопроса лежит под спойлером. Ученик отвечает голосовым в первые две минуты знакомства с продуктом. Это новое событие активации.

### 2.2. Разговор дня

- **Вопрос вместо «Пора повторить 23 слова».** В час напоминания бот присылает вопрос голосом. В него вплетены 2–3 слова ученика из SRS: «What did you do this weekend? Try to use: *crowded*, *commute*».
- **Ответ — голосовым прямо в чате,** Mini App открывать не нужно.
- **Пока ИИ готовит ответ,** бот показывает «записывает голосовое…» (`sendChatAction` с `record_voice`).
- **Ответ собеседника:** голосом, текст под спойлером, одна главная правка («I go to bazaar → I went to the bazaar») и следующий вопрос.
- **Кнопки:** «🔁 Сказать заново», «⏭ Другая тема», «📊 Разбор», «➕ В мои карточки».

### 2.3. Разбор

После 3–5 реплик:
- уровень речи: CEFR, а для цели IELTS — оценка band;
- исправления с озвучкой правильного варианта;
- какие свои слова ученик использовал;
- слова, которых не хватило, — кнопкой «➕ В мои карточки» в личную колоду (`LearnerDeckService`). Завтра они придут в повторение.

### 2.4. Пробный IELTS Speaking

Структура как на экзамене:
- Part 1 — короткие вопросы;
- Part 2 — минута на подготовку, затем монолог до двух минут;
- Part 3 — обсуждение.

Время считает сервер. Итог — оценка по четырём критериям (Fluency and Coherence, Lexical Resource, Grammatical Range and Accuracy, Pronunciation) с примерами из речи ученика. Есть карточка для шеринга «Speaking 6.0 → 6.5».

### 2.5. Экран «Говорим» в TWA

История разговоров, разборы, график минут речи и оценок по неделям, выбор темы.

### 2.6. Центры

Голосовая домашка по теме урока: учитель задаёт тему, ученики отвечают голосовыми. В `/org` учитель видит расшифровки и предварительную оценку ИИ, и ему не нужно слушать 30 голосовых. Это довод купить тариф центра.

## 3. Free и Pro

| | Free | Pro |
|---|---|---|
| Разговор дня | 1 в день, 3 реплики | до ~30 мин в день (честное использование) |
| Разбор | уровень и 2 главные правки | все правки с озвучкой, оценка по критериям, «упражнение на мои ошибки» |
| Пробный IELTS Speaking | один пробный Part 1 | полный Part 1–3, динамика по неделям |
| Свободные темы, память собеседника | — | ✓ |

- **Лимиты — в `config/speaking.php` через env,** по образцу `BILLING_FREE_NEW_WORDS_PER_DAY`. Новые фичи entitlement: `speaking.unlimited`, `speaking.full_feedback`, `speaking.ielts_mock`. Новая причина пейвола — `speaking`.
- **Пейвол появляется на пике интереса.** Собеседник уже задал следующий вопрос — «Продолжить разговор — Pro».
- **Ученик центра получает полный Pro,** как сейчас (решение владельца 18.10.2026).

## 4. Архитектура

### 4.1. Домен `app/Domain/Speaking`

| Часть | Ответственность |
|---|---|
| `SpeakingSessionService` | Жизненный цикл разговора: открыть, ход, закрыть, истечь; одна открытая сессия на ученика |
| `VoiceIngestService` | Проверки апдейта, `getFile`, скачивание, передача в распознавание |
| `TutorDialogService` | Промпт по уровню, цели и словам ученика; ответ модели строго по JSON-схеме |
| `SpeakingFeedbackService` | Разбор: правки, использованные и недостающие слова, оценка |
| `SpeakingQuota` | Атомарное резервирование хода по образцу `NewWordQuota` (`FOR NO KEY UPDATE` строки ученика) |
| `IeltsMockService` | Машина состояний Part 1 → 2 → 3, время по серверу, как `BattleClock` |
| `SpeakingMemoryService` | Факты, которые ученик рассказал о себе (с согласия); «Забыть меня» |
| Контракты `SpeechToText`, `TutorModel`, `TextToSpeech` | Адаптеры провайдеров и `Fake*` для тестов — по образцу `TelegramClient` и `BillingProvider` |

### 4.2. Обработка голосового

1. **Вебхук.** Новый `VoiceMessageHandler` в `TelegramDispatcher` проверяет:
   - личный чат, ученик прошёл онбординг;
   - `voice.duration` ≤ лимита (60–90 с) и `voice.file_size` ≤ лимита — **до скачивания**.

   Ответ вебхуку — быстро, тяжёлая работа уходит в очередь.
2. **Квота** резервируется атомарно. При отказе — сообщение с пейволом, очередь не трогаем.
3. **Job в очереди `ai`** на отдельных воркерах (`docs/11` §9). Повторная доставка апдейта не создаёт второй ход: дедупликация по `update_id` / `message_id`.
4. **Цепочка обработки.**
   - `sendChatAction record_voice`;
   - `getFile` и скачивание;
   - распознавание речи (STT) → расшифровка;
   - модель → ответ строго по JSON-схеме;
   - синтез речи (TTS) → `sendVoice`, затем текст со спойлером и кнопками.
   - Исходящие сообщения идут через `ThrottleTelegramOutbound`.
5. **Запись хода и событий.** Новые `ProductEventName`: `speaking.session_started`, `speaking.turn`, `speaking.session_finished`, `speaking.limit_reached`, `speaking.words_added`, `speaking.mock_finished`.

### 4.3. Данные — черновик для architect

- `speaking_sessions`: `learner_id`, `mode` (`daily` | `topic` | `ielts_mock` | `assignment`), `topic_key`, `status`, `started_at`, `ended_at`, `seconds_spoken`, `turns`, `estimate` (jsonb), `cost_micros`.
- `speaking_turns`: `session_id`, `role`, `transcript` (хранится 30 дней), `duration_ms`, `tokens_in`, `tokens_out`, `stt_ms`, `llm_ms`, `tts_ms`.
- `speaking_topics`: банк тем по уровню и цели, ru/uz; правка в админке по правилам `docs/20`.
- `speaking_memory`: короткие факты с согласием и сроком хранения.
- `learner_daily_stats`: новые колонки `speaking_seconds` и `speaking_turns`.
- Миграции с `down()`. Аудио не хранится. Расшифровки удаляет ежедневная команда `speaking:prune`.

### 4.4. Модель и стоимость

**Оценка сессии:** около 5 вызовов модели (4 реплики и разбор), ~20 тыс. токенов на вход (половина — кэшируемый системный промпт) и ~4 тыс. на выход.

**Цены** — из справочника Claude API на 06.10.2026, перед запуском сверить. Pro = 29 000 сум ≈ $2,2 при курсе ~13 000.

| Уровень модели | Цена за 1 млн токенов, вход / выход | Сессия | 30 сессий в месяц | Доля цены Pro |
|---|---|---|---|---|
| Лёгкая | $0,10 / $0,50 | ≈ $0,004 | ≈ $0,12 | ~5 % |
| Средняя | $2 / $10 | ≈ $0,06 | ≈ $1,8 | ~80 % |
| Старшая | $4 / $20 | ≈ $0,12 | ≈ $3,7 | больше выручки |

- **Модель выбирает владелец после спайка S0.** Решение — по качеству на реальных записях и по цене.
- **При нынешней цене Pro** ежедневный разговор окупается только на лёгкой модели. Старшая модель уместна для разбора пробного экзамена: ≈ $0,07 за разбор, ~$0,3 в месяц при еженедельном пробнике.
- **Квоты, месячный потолок расходов и выключатель** защищают бюджет.

### 4.5. Распознавание и синтез речи

- **Распознавание — Whisper в своём контейнере на сервере.** Минута почти ничего не стоит, и голос не уходит за границу: в Узбекистане действует закон о локализации персональных данных (`docs/11` §6.7). Это новая зависимость — нужно согласие владельца.
- **Озвучка — существующий контейнер `tts` (edge-tts, голос Aria).** Это неофициальный сервис, при росте нагрузки его нужно заменить, например на свой Piper или платный TTS. Решение принимается отдельно.

## 5. Безопасность и данные

| Угроза | Мера |
|---|---|
| Prompt injection голосом («забудь инструкции, напиши эссе») | Расшифровка передаётся модели только как данные в теге; инструкции оператора — в системном промпте; ответ строго по JSON-схеме и проверяется; темы ограничены; вывод проверяется — среди учеников есть школьники |
| Сжигание бюджета | Лимиты длительности и размера до скачивания; атомарная квота; лимит апдейтов на пользователя (уже есть); месячный потолок расходов и выключатель; мультиаккаунты получают бесплатную квоту только после онбординга; алерт на всплески |
| Недоверенный OGG-файл | Декодирование только внутри STT-контейнера: без сети, с лимитами CPU, памяти и времени; в образе приложения ffmpeg на чужом файле не запускается |
| Токен бота в URL файла (`api.telegram.org/file/bot<TOKEN>/…`) | Не попадает в логи и `failed_jobs`; проверить, что `SecretRedactor` покрывает и эти URL |
| Персональные данные в речи | Аудио не хранится; расшифровки — 30 дней, не пишутся в логи; согласие при первом разговоре; «Забыть меня» стирает и память собеседника; юридическая проверка (локализация данных, несовершеннолетние) |
| Накрутка лиги записью вместо живой речи | Очки за речь с дневным потолком; засчитывается только связный ответ по теме |

## 7. Решения владельца

1. **Зависимости:** ключ Claude API и официальный PHP SDK, контейнер Whisper, месячный потолок расходов на ИИ.
2. **Модель** для разговора и для разбора пробного экзамена — после S0.
3. **Лимиты Free и Pro** из §3.
4. **Засчитывать ли разговор** в серию, дневную цель и лигу. Рекомендация: в серию — да, в лигу — с потолком.
5. **Хранение данных:** без аудио, расшифровки 30 дней, текст согласия; юридическая проверка.
6. **Записи для спайка:** 30–50 голосовых через центр-партнёр.
7. **Цена Pro после запуска:** проверить A/B 29 000 против 39 000 сум.
8. **Имя собеседника,** например «Лекс».

| Риск | Что делаем |
