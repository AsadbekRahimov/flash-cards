# 11. Анализ системы и стратегия развития LexiFlow Pro как SaaS

> Дата анализа: 2026-10-17, ред. 2 — 2026-10-18 (стратегия изменена на **B2C-first**).
> База: ветка `master` после PR #12 (коммит `cc984c3`).
> Источники: весь `docs/`, `PROGRESS.md`, код `app/`, `routes/`, `database/migrations/`, `resources/twa/`, CI и Docker-конфиги.
> Документ дополняет и по стратегии **заменяет** [10_B2C_EXPANSION.md](./10_B2C_EXPANSION.md): там — список идей, здесь — аудит того, что есть на самом деле, найденные проблемы и выбранный путь к SaaS с приоритетами.

### Решение владельца продукта (2026-10-18)

1. **Основной сегмент — студенты из разных регионов**, а не только ученики учебных центров. Продукт **публичный**: любой человек находит бота, начинает учить слова на флеш-картах и готовится к экзаменам.
2. **Платные тарифы — для всех** (freemium: бесплатный базовый уровень + подписка Pro).
3. **Учебные центры и репетиторы — дополнительный канал.** Центр платит **фиксированную сумму раз в месяц**, и **все его студенты занимаются без ограничений** (получают Pro, пока состоят в центре).

## 0. Executive summary

**Что есть.** Хорошо сделанный MVP «одного учебного центра»: Telegram-бот + Mini App (TWA) + Filament-админка. Ядро (SM-2, экзамены, лидерборд, initData/JWT, 2FA, rate limit, Group Lock) аккуратное, покрыто тестами (180 Pest + 15 Vitest), Larastan level 8 проходит без baseline, CI и production-деплой готовы.

**Главный разрыв с новой стратегией.** Сейчас продукт **не может существовать без учителя и группы**: студент — это запись `students` внутри Telegram-группы, тренировка начинается только по команде учителя, контент заливает только админ, в личке бот отвечает «аккаунт не привязан к учителю». Для публичного B2C всё это надо развернуть: **в центре системы — ученик (learner)**, а группа, учитель и центр становятся необязательной надстройкой.

**Что нужно построить (по приоритету):**
1. **Learner-first модель:** один профиль на Telegram-пользователя, личный прогресс, самостоятельный старт через `/start` в боте.
2. **Публичная библиотека курсов** (CEFR A1–C2, IELTS/SAT/школьные темы) с переводами на узбекский, русский и другие языки региона — это главный актив и отличие от конкурентов.
3. **Самостоятельное обучение без учителя:** домашний экран «Сегодня», тренировка всех due-слов, streak, дневная цель.
4. **Freemium + Pro** с оплатой через **Telegram Stars** внутри Telegram и через Payme/Click/карты на вебе.
5. **Тариф для центра:** фиксированная месячная оплата по размеру центра → все привязанные студенты получают Pro.
6. Мониторинг, продуктовая аналитика, i18n — без них B2C вслепую.

**Порядок работ (кратко):**
1. **Фаза 0 (2–3 недели):** исправить блокеры ядра (раздел 3.1) + аналитика и мониторинг.
2. **Фаза 1 (5–7 недель):** learner-first модель, онбординг в боте, личное обучение, публичная библиотека, Free/Pro, Telegram Stars.
3. **Фаза 2 (4–6 недель):** удержание и рост (streak, лиги, рефералка, свои колоды), тариф для центров на новой модели.
4. **Фаза 3:** AI-фичи, веб-версия вне Telegram, новые рынки и языки.

### 1.2 Пользовательские сценарии, которые реально работают

1. Админ создаёт учителя, привязывает Telegram ID, активирует группу, которую бот поймал через `my_chat_member`.
2. Админ импортирует урок JSON (stage → lesson → words).
3. Учитель в группе: `/start_training [stage lesson]` (или выбор урока кнопками), `/start_exam`, `/close_exam`, `/stats` (в ЛС).
4. Студент жмёт кнопку → TWA → initData HMAC → JWT 15 мин → карточки с 3 оценками / экзамен MCQ с серверным таймером.
5. По окончании экзамена — лидерборд в группу (идемпотентно, `leaderboard_posted_at`).
6. Ежедневно в 18:00 UTC — напоминание студенту в ЛС, если ≥ 5 слов к повторению.

**Чего нет для B2C:** человек, который сам нашёл бота, сейчас **не может сделать ничего** — ни выбрать курс, ни начать учить.

### 1.3 Сильные стороны (их надо сохранить)

- **Нулевое трение:** нет регистрации и установки приложения — Telegram уже есть у всех в регионе. Для B2C это ещё важнее, чем для B2B.
- **Безопасность выше среднего для MVP:** корректная валидация initData (`hash_equals`, ручной парсинг без `parse_str`, проверка `auth_date` и future skew), JWT с проверкой issuer и отзывом при деактивации группы, серверный таймер экзамена, защита от двойного ответа на уровне БД, 2FA с одноразовыми recovery-кодами под `FOR UPDATE`, IP allowlist и секрет вебхука, маскирование PII в логах, CSP/HSTS.
- **Конкурентность продумана:** частичные unique-индексы на открытые сессии, `lockForUpdate` в ответах экзамена, идемпотентная публикация лидерборда.
- **Чистые границы:** Telegram SDK за адаптером, бизнес-логика в `Domain/*/Services`, `PanelDataScope` для учителя. SM-2 изолирован — его можно заменить.
- **Процесс:** Pint + Larastan 8 + Pest в CI, мульти-агентный workflow описан в `CLAUDE.md`.

## 3. Продуктовые проблемы текущего ядра

### 3.1 🔴 Исправить до публичного запуска

1. **Напоминания не доходят.** Бот может написать в ЛС только тому, кто сам открыл с ним диалог. `/start` в ЛС отвечает студенту «аккаунт не привязан к учителю» (`StartCommandHandler`). `SendReviewReminderJob` не обрабатывает 403 `bot can't initiate conversation`: лог не пишется, задание падает и ставится заново каждый день.
   В B2C это решается естественно: **каждый пользователь начинает с `/start` в ЛС бота**, значит доступ к ЛС есть по умолчанию. Нужно: онбординг в `/start`, поле `learners.dm_blocked_at` (при 403 — пометить и не слать), настройка времени напоминаний.

2. **Время рассылки 18:00 UTC = 23:00 в Ташкенте.** Для разных регионов нужен **часовой пояс пользователя** (выбор при онбординге / по `language_code` + ручная правка) и рассылка каждые 15 минут по локальному времени.

3. **Кнопка «Средне» постепенно портит интервалы.** TWA отправляет оценки 2/3/5. По формуле SM-2 оценка 3 *уменьшает* EF (−0.14), 2 сбрасывает повторения и уменьшает EF на 0.32. Студент, который честно жмёт «Средне», упирается в EF = 1.30 («ease hell»): повторений всё больше, мотивация падает. В B2C это прямой отток.
   **Минимум:** перемаппить «Средне» на 4 (EF без изменения) — решение для `architect`. **Среднесрочно:** FSRS (4.1).

4. **«Трудное» слово не возвращается в той же сессии** (при q < 3 интервал = 1 день). Нужны learning steps (1 мин, 10 мин) внутри сессии.

5. **Экзамен легко списать.** Одинаковый порядок вопросов и вариантов у всех (`ExamQuestionBuilder` строит набор один раз). Нужно детерминированное перемешивание per-student (seed = `hash(session_id, learner_id)`) и замена заглушек `— (filler #N)` реальными дистракторами из библиотеки. Для публичных лиг/рейтингов честность ещё важнее.

### 3.2 🟠 UX-пробелы (для B2C — критичны)

- **Нет домашнего экрана.** `LandingView` говорит «откройте тренировку через кнопку в группе». Нужен экран: «Сегодня: 23 слова к повторению · 10 новых · серия 5 дней · [Начать]».
- **Нет выбора курса.** Каталог: язык обучения → уровень → курс → уроки, с прогрессом.
- **Только одно направление:** слово → перевод. Нет обратного направления, ввода, аудирования.
- **Нет разбора ошибок после экзамена** и кнопки «добавить ошибки в повторение».
- **Импорт только JSON и только админом.** Для «своих колод» пользователю нужен ввод списком «word — перевод», CSV, позже Anki.

## 4. Рекомендации по ядру обучения

### 4.1 Алгоритм повторений: SM-2 → FSRS

FSRS — современный алгоритм (используется в Anki с 2023 года): меньше повторений при той же запоминаемости, хорошо работает с 3–4 кнопками.

План (`architect` → `coder`):
1. Интерфейс `SchedulerAlgorithm::schedule(state, rating, now): state`; SM-2 — первая реализация.
2. В `word_repetitions` поля `stability`, `difficulty`, `state` (new/learning/review/relearning), `lapses`; SM-2 поля оставить для отката.
3. FSRS с параметрами по умолчанию, флаг алгоритма для A/B-теста.
4. Позже — персональная оптимизация параметров по истории `training_reviews` (ночной job; можно сделать Pro-фичей).

### 4.2 Новые типы упражнений

| Упражнение | Ценность | Сложность | Тариф |
|---|---|---|---|
| Обратная карточка (перевод → слово) | высокая | низкая | Free |
| Аудио-карточка: слушаешь → выбираешь/пишешь | высокая | низкая (TTS есть) | Free/Pro |
| Ввод слова (spelling) с допуском опечаток | высокая | средняя | Pro |
| Gap-fill по `example` | высокая | низкая | Pro |
| Matching (5 пар) | средняя | средняя | Free |
| Тест-симулятор (IELTS/SAT vocab) с таймером | высокая для подготовки | средняя | Pro |
| AI-проверка своего предложения | высокая | средняя (LLM API) | Pro+/AI |
| Произношение (запись → STT → оценка) | «вау» | высокая | Pro+/AI |

### 4.3 Мотивация и удержание (для B2C это главное)

- **Streak и дневная цель** (5/10/20 мин или слов) + «заморозка» streak — самый дешёвый и сильный рычаг удержания; заморозки — часть Pro.
- **Лиги** (недельный рейтинг из 30 случайных пользователей близкого уровня, повышение/понижение) — соревновательность без Telegram-группы.
- **Друзья и вызовы:** пригласил друга → сравнение streak, дуэль по колоде.
- **Карточки для шеринга** (картинка «выучил 500 слов», «30 дней подряд») в истории/каналы Telegram — органический рост.
- **Групповые механики сохраняются** для центров и для чатов друзей: бот в любой группе, недельные итоги в чат.

## 5. Архитектура: learner-first + организации-спонсоры

### 5.1 Центральная идея

```
Learner (Telegram-пользователь)  ← главный объект, у него прогресс, streak, подписка
   ├── личная подписка (Free / Pro)               — платит сам
   ├── membership в организации (центр/репетитор) — Pro оплачивает организация
   └── membership в Telegram-группе (необязательно) — групповые тренировки, экзамены, рейтинг
```

**Доступ к функциям (entitlement)** считается одним сервисом:
`effective_plan(learner) = max(личная подписка, лучший активный спонсорский план из memberships)`.
Ученик центра получает Pro, пока центр оплачивает и пока ученик в нём состоит. Ушёл из центра — откат на Free (или его личную подписку), **прогресс остаётся у него**.

### 5.2 Изменения схемы (черновик для `architect`)

> **Уточнено в docs/12 (§1, §2, §13).** Актуальная схема Фазы 1 — там. Главные отличия: переноса данных `students` → `learners` **нет** (владелец: прода с данными нет; create-миграции правятся на месте, `migrate:fresh --seed`), поэтому правило слияния по `repetitions` не применяется; `learner_sessions` → режим `training_sessions.mode`; `usage_counters` → `learner_daily_stats`; `events` → уже существующая `product_events`; `organization_users`/`organization_members`/`assignments`/`payments` — Фаза 2 или вместе с оплатой; `word_translations.language` → `locale` (`ru`/`uz`); RLS отложен.

```
                       (public|unlisted|private), target_language, level (A1..C2), exam_tag
                       (IELTS|SAT|school|…), title, status (draft|review|published)
lessons                + course_id
words                  word, transcription, part_of_speech, example, audio_path
word_translations      word_id, language (uz|ru|kk|ky|tg|tr|…), translation, example_translation
word_repetitions       learner_id (вместо student_id), word_id, + поля FSRS
learner_sessions       learner_id, course_id/lesson_id NULL, mode (daily|lesson|test), source
                       (self|assignment|reminder), started_at, ended_at
assignments            organization_id/telegram_group_id, lesson_id, type (training|exam), due_at
subscriptions          id, subscriber_type (learner|organization), subscriber_id, plan, status
                       (trialing|active|past_due|canceled|expired), period_start, period_end,
                       provider (telegram_stars|payme|click|stripe|manual), provider_ref
payments               subscription_id, provider, provider_event_id UNIQUE, amount, currency, raw jsonb
usage_counters         subscriber_type, subscriber_id, period, new_words, ai_requests, tts_seconds
events                 id, learner_id NULL, organization_id NULL, name, props jsonb, created_at
```

Ключевые правила:
- **Миграция без потери данных:** для каждого уникального `students.telegram_user_id` создать `learner`, слить `word_repetitions` (при конфликте одного слова — брать запись с большим `repetitions`), `students` → `group_members`; текущие уроки — в курс платформы «Default».
- **Изоляция:** данные организаций (участники, задания, отчёты) — через global scope по `organization_id` + **Postgres RLS** как второй рубеж; Pest-тесты «учитель центра A не видит учеников центра B» на каждый ресурс и эндпоинт.
- **Приватность ученика:** центр видит прогресс ученика **только пока тот состоит в центре** и только по учебным метрикам; личные колоды ученика центру не видны.
- JWT TWA: `sub = learner_id`, без `gid`; контекст группы/центра передаётся параметром и проверяется политикой.

### 5.3 Боты

- **Один публичный бот платформы** — основной вход для всех (B2C и центров).
- Центр привязывает свою группу кодом (`/link ABC123` в группе) или раздаёт ученикам deep-link `t.me/<bot>?start=org_<code>` — ученик сразу попадает в центр и получает Pro.
- **White-label бот** (свой бот центра) — опция крупного тарифа позже: токен шифруется отдельным ключом, webhook `/telegram/webhook/{bot_id}/{secret}`, `InitDataValidator` выбирает токен по боту.

### 5.4 Роли

Суперадмин платформы (отдельная панель `/platform`, impersonation только с аудитом) → `owner` центра (оплата) → `admin` центра → `teacher` → `learner`. Модераторы публичного контента — отдельная роль платформы.

## 6. Стратегия SaaS: B2C-first + тариф для центров

### 6.1 Позиционирование

> **«LexiFlow — учи слова для экзаменов и жизни прямо в Telegram. Карточки с умными повторениями, озвучка и тесты — на твоём родном языке, без установки приложения.»**

Почему это может выиграть у Duolingo/Anki/Quizlet в регионе:
- **Переводы и интерфейс на узбекском (и других языках региона)** — у глобальных приложений этого либо нет, либо плохо.
- **Подготовка к конкретным целям** региона: IELTS, SAT, CEFR-сертификат, вступительные/школьные программы — курсы под цель, а не «просто английский».
- **Telegram вместо App Store:** нет установки, работает на слабых телефонах и медленном интернете.
- **Мост с учебными центрами:** ученик центра приходит в продукт бесплатно для себя, а после окончания курса может остаться на личном Pro — центры становятся каналом привлечения B2C.

### 6.2 Сегменты

1. **Самостоятельные студенты** (школьники старших классов, студенты, взрослые 16–35) — основной сегмент и основной доход.
2. **Ученики учебных центров** — приходят через центр, Pro оплачивает центр.
3. **Учебные центры** — платят фиксированную подписку, получают кабинет, задания, отчёты.
4. **Репетиторы** — маленький тариф центра (до 20–30 учеников).

### 6.3 Тарифы (гипотезы — проверить A/B-тестами цены и интервью)

**Для студентов:**

| Тариф | Что входит | Ориентир цены |
|---|---|---|
| **Free** | все публичные курсы, лимит новых слов в день (например, 15–20), повторения без ограничений*, базовые упражнения, реклама собственных курсов допустима, но без сторонней рекламы | 0 |
| **Pro** | без лимита новых слов, все типы упражнений, тест-симуляторы IELTS/SAT, свои колоды, аудио офлайн-кэш, заморозки streak, подробная статистика | ~$2–3 / мес в регионе; скидка при оплате за год |
| **Pro + AI** (позже) | AI-генерация колод из текста, проверка предложений, произношение | ~$5–6 / мес или пакеты |

\* **Повторения не ограничивать никогда** — иначе пользователь теряет уже выученное и уходит. Ограничивать новые слова и продвинутые функции.

**Для центров и репетиторов (фиксированная оплата раз в месяц, студенты занимаются без ограничений):**

| Тариф | Учеников с Pro | Что ещё | Ориентир цены |
|---|---|---|---|
| **Tutor** | до 30 | кабинет, свои колоды, задания, отчёты | фикс. ~$10 / мес |
| **Center S** | до 100 | + несколько учителей, привязка групп, экзамены с лидербордом | фикс. ~$25–30 / мес |
| **Center M** | до 300 | + отчёты родителям, экспорт, аналитика групп | фикс. ~$60–70 / мес |
| **Center L / сеть** | 300+ | + white-label бот, брендинг, API, SLA | индивидуально |

Почему **фиксированная цена по размеру**, а не «безлимит за одну цену»:
- центру проще планировать бюджет — это то, что вы хотите («платит раз в месяц, студенты занимаются сколько угодно»);
- без ограничения мест появится злоупотребление: «центр» на 5000 человек, продающий доступ к Pro дешевле вас. Лимит мест защищает B2C-доход;
- переход на следующий тариф при росте центра — естественный upsell.

Правила спонсорского доступа:
- Ученик центра получает **полный Pro** (не только контент центра) — так ценность для центра максимальна.
- Место освобождается, когда центр удаляет ученика или тот выходит; лимит считается по активным участникам.
- Центр видит, кто занимает места; подозрительный рост (сотни входов по одному коду за день) — алерт и ручная проверка.
- После ухода из центра ученику показывается предложение личного Pro со скидкой на первый месяц — мост B2B → B2C.

### 6.4 Оплата

- **Внутри Telegram (бот/Mini App) — Telegram Stars.** По правилам Telegram цифровые товары и услуги внутри бота/Mini App продаются за Stars (`sendInvoice`/`createInvoiceLink` с валютой `XTR`, подписки через `subscription_period`). Stripe/ЮKassa через Telegram Payments для цифровых подписок не подходят. Учтите: Stars выводятся с задержкой и комиссией — **перепроверить актуальные правила и условия вывода перед запуском**.
- **Вне Telegram — веб-кабинет** (лендинг + оплата): **Payme, Click, Uzum** для Узбекистана, карты/Stripe/Paddle для других стран. Там же платят центры (плюс счёт и перевод для юрлиц).
- Архитектура: интерфейс `BillingProvider` (`TelegramStarsProvider`, `PaymeProvider`, `ClickProvider`, `ManualInvoiceProvider`), одна таблица `subscriptions`, идемпотентная обработка webhook'ов по `provider_event_id`, `past_due` + grace period, затем откат на Free (данные не удаляются). Это деньги и конкурентность — **задача для `architect`**.

### 6.5 Контент — главный актив B2C

Публичному продукту нужен **готовый качественный контент с первого дня**:
- Курсы MVP: английский A1–B2 (Top-3000 слов по уровням), IELTS Academic vocab, SAT vocab, темы (путешествия, IT, бизнес).
- Переводы: узбекский (латиница) и русский — с первого дня; казахский, кыргызский, таджикский, турецкий — по мере выхода на рынки.
- Производство: AI-черновик (перевод, пример, транскрипция) → проверка носителем/преподавателем → публикация. Статусы `draft → review → published` в админке.
- Аудио: предгенерация TTS для всей библиотеки.
- Позже — **пользовательские и community-колоды** с модерацией (рост контента силами пользователей и центров; центр может опубликовать свой курс публично — бесплатная реклама центра).
- Целевой язык обучения в модели данных — параметр (`target_language`), чтобы позже добавить корейский/немецкий/турецкий без переделки.

### 6.6 Каналы роста

- **Telegram-каналы и блогеры** по подготовке к IELTS/SAT в регионе — основной платный канал.
- **Реферальная программа:** пригласил друга → оба получают 7 дней Pro.
- **Учебные центры как канал:** каждый центр приводит десятки учеников, часть остаётся на личном Pro.
- **Шеринг достижений** и **публичный рейтинг** по городам/регионам («топ Ташкента недели»).
- **SEO-лендинги** («500 слов IELTS с переводом на узбекский») со ссылкой на бота.

### 6.7 Право и соответствие (проверить с юристом)

- **Узбекистан, закон «О персональных данных»:** с 2021 года персональные данные граждан РУз должны храниться на серверах на территории Узбекистана. Для публичного продукта с пользователями из РУз — хостинг основной БД в UZ (или гибрид).
- **Несовершеннолетние:** среди школьников много < 18 — минимизация данных (сейчас хранится только Telegram-профиль — это хорошо), оферта с учётом возраста, никакой сторонней рекламы.
- Публичная оферта, политика конфиденциальности, правила возврата, удаление аккаунта и экспорт данных по запросу.
- Налоги и приём платежей: юрлицо/ИП, договоры с Payme/Click, учёт выручки в Stars.

## 8. Безопасность при переходе к публичному SaaS

У публичного продукта другая модель угроз: много анонимных пользователей, деньги, пользовательский контент.

| Угроза | Мера |
|---|---|
| Утечка данных между центрами / доступ центра к чужим ученикам | global scope + Postgres RLS + тесты изоляции; доступ центра к learner только через активное membership |
| Фрод в оплате (повтор webhook, подделка, двойное зачисление) | проверка подписи провайдера, `provider_event_id UNIQUE`, IP allowlist, сверка суммы и валюты, идемпотентный `SubscriptionService` |
| Злоупотребление спонсорским Pro (перепродажа мест центра) | лимит мест, алерты на аномальные вступления, ручная модерация центров, срок жизни invite-кодов |
| Фарм рефералов и рейтингов (боты, мультиаккаунты) | награда только после активности приглашённого (например, 3 дня занятий), rate limit по `telegram_user_id`, анти-чит в лигах (лимит XP/мин) |
| Replay initData | сократить `TWA_INIT_DATA_MAX_AGE` с 24 ч до ~1 ч |
| JWT без отзыва | `jti` + denylist в Redis, привязка к learner, короткий TTL уже есть |
| Пользовательский контент (колоды, community) | экранирование (XSS уже закрыт для текущего вывода — проверить новые экраны), модерация публичных колод, жалобы, фильтр запрещённого контента |
| Prompt injection в AI-фичах | пользовательский текст только как данные, строгая JSON-схема вывода, квоты |
| Захват аккаунта владельца центра | обязательная 2FA для `owner`/`admin` центра, уведомления о входах |
| DoS публичных эндпоинтов | rate limit per-learner + per-IP, кэш каталога, CDN для статики TWA и аудио |

Процессы: `composer audit`/`npm audit` (уже в CI), Dependabot, Semgrep для PHP/Laravel, OWASP ZAP baseline на staging в CI, внешний пентест перед публичным запуском, `security.txt` и responsible disclosure.

## 9. AI-фичи: где окупаются

1. **Производство контента библиотеки** (внутренний инструмент, окупается первым): AI-черновик перевода на uz/ru, пример, транскрипция → ручная проверка. Ускоряет выпуск курсов в разы.
2. **«Колода из текста»** (Pro+AI): вставил статью/субтитры → выбраны незнакомые слова по уровню → колода.
3. **Проверка предложения со словом** и короткий фидбек на родном языке.
4. **Правдоподобные дистракторы** для тестов (та же часть речи, близкий смысл).
5. **Персональный план** на день по истории ошибок.

Технически: очередь `ai` с отдельными воркерами, кэш по хешу запроса, квоты в `usage_counters`, модель уровня Claude Haiku 5.5 для массовых задач и Sonnet 5.5 для генерации контента; вывод — строгий JSON, проверяемый тем же `VocabularyImporter`.

| Риск | Вероятность | Митигация |
|---|---|---|

## 13. Скорость передачи данных и сжатие (задача 0.8)

**Что уже есть** (`docker/nginx/prod.conf`): `gzip on`, уровень 6, `gzip_min_length 1024`, типы JSON/JS/CSS/SVG/текст; HTTP/2; `immutable`-кэш для `/twa/assets/`; TWA уже получает следующую карточку в ответе на `review` (меньше запросов).

**Что добавить:**

| Мера | Эффект | Как |
|---|---|---|
| Предсжатая статика TWA (`.gz` рядом с файлами) + `gzip_static on` | максимальное сжатие (уровень 9) без нагрузки на CPU при каждом запросе | шаг сборки: Node-скрипт на встроенном `zlib` (без новых зависимостей) после `vite build` |
| Brotli | ещё −15–20% к gzip для JS/CSS | в `nginx:alpine` модуля нет — позже, отдельным образом/модулем (после согласования) |
| `gzip_min_length` 1024 → 512 | сжимаются ответы API с карточками и вопросами | ответы < 512 байт не сжимать — выигрыша нет, только накладные расходы |
| Доп. типы: `application/manifest+json`, `application/xml`, `font/ttf`, `font/otf` | | `woff2`, `mp3`, `png/jpg/webp` **не** сжимать — уже сжаты |
| Аудио TTS | gzip бесполезен для mp3 | кэш `Cache-Control` (уже есть), CDN позже |
| Защита от BREACH | gzip + HTTPS + секрет в ответе (CSRF-токен Filament) + отражённый ввод — классический вектор | `gzip off` для `/admin`, `/2fa`, `/livewire-` (HTML админки маленький, трафик ничтожный); `SESSION_SAME_SITE=lax` уже стоит; JSON API TWA не содержит CSRF-токенов, JWT берётся из initData — для API сжатие оставляем |
| Проверка | | smoke-тест: `curl -sI -H 'Accept-Encoding: gzip' …/twa/assets/*.js` → `Content-Encoding: gzip`; Lighthouse ≥ 90 |

**Реализовано (задача 0.8):**
- ✅ Предсжатая статика: `resources/twa/scripts/precompress.mjs` (встроенный `zlib`, gzip level 9, файлы ≥ 512 байт, `.gz` только если меньше), подключён в `npm run build` после `vite build`; `gzip_static on` для `/twa/`; `.gz` попадают в Docker-образ через существующий `COPY public/twa`.
- ✅ `gzip_min_length 512` и новые типы (`manifest+json`, `xml`, `font/ttf`, `font/otf`) — в `docker/nginx/prod.conf` и `default.conf`.
- ✅ BREACH: `/admin`, `/2fa`, `/livewire-` вынесены в отдельный regex-`location` с `gzip off` и прямым `fastcgi_pass` на `index.php` (`gzip off` внутри `try_files`-location не работает: внутренний редирект уходит в `location ~ \.php$`, где gzip включён).
- ✅ Тест скрипта (vitest) и описание в `docs/DEVOPS_GUIDE.md` (раздел «Compression and BREACH», smoke-проверки).
- ⏳ Brotli, Lighthouse ≥ 90 и CDN — не сделаны (Brotli — после согласования отдельного образа/модуля).

Дальше (Фаза 1+): ответы API компактнее (Resource-классы без лишних полей), предзагрузка аудио следующей карточки, CDN для статики и аудио при росте аудитории.
