# 11. Анализ системы и стратегия развития LexiFlow Pro как SaaS

> Дата анализа: 2026-10-17. База: ветка `master` после PR #12 (коммит `cc984c3`).
> Источники: весь `docs/`, `PROGRESS.md`, код `app/`, `routes/`, `database/migrations/`, `resources/twa/`, CI и Docker-конфиги.
> Документ дополняет [10_B2C_EXPANSION.md](./10_B2C_EXPANSION.md): там — список идей для B2C, здесь — аудит того, что есть на самом деле, найденные проблемы и рекомендуемый путь к SaaS с приоритетами.

## 0. Executive summary

**Что есть.** Хорошо сделанный MVP «одного учебного центра»: Telegram-бот + Mini App (TWA) + Filament-админка. Ядро (SM-2, экзамены, лидерборд, initData/JWT, 2FA, rate limit, Group Lock) аккуратное, покрыто тестами (180 Pest + 15 Vitest), Larastan level 8 проходит без baseline, CI и production-деплой готовы. С инженерной стороны продукт **готов к пилоту**.

**Чего нет для SaaS.** Система рассчитана ровно на одного клиента: нет понятия «организация/арендатор» (tenant), контент общий для всех, один бот на всех, нет самостоятельной регистрации центра, нет биллинга, тарифов, лимитов, продуктовой аналитики и мониторинга. Есть и несколько продуктовых дыр, которые помешают даже пилоту: напоминания студентам почти наверняка не доходят, время рассылки — 23:00 по Ташкенту, кнопка «Средне» со временем ухудшает интервалы.

**Главная рекомендация.** Не идти сразу в массовый B2C (конкуренция с Duolingo/Anki и правила оплаты Telegram), а сначала стать **вертикальным B2B SaaS для языковых центров и репетиторов в Узбекистане/Центральной Азии**: «Telegram-класс под ключ». B2C добавлять позже, на той же мультиарендной основе.

**Порядок работ (кратко):**
1. **Фаза 0 (1–2 недели):** исправить блокеры пилота (раздел 3.1).
2. **Фаза 1 (4–6 недель):** мультиарендность + онбординг центра + тарифы/лимиты + базовая аналитика.
3. **Фаза 2 (4–6 недель):** ценность для учителя: свой контент, домашние задания, отчёты родителям, новые типы упражнений.
4. **Фаза 3:** white-label бот, AI-фичи, B2C-канал для одиночек, выход на соседние рынки.

## 1. Что представляет собой система сейчас

### 1.1 Компоненты

| Компонент | Технологии | Состояние |
|---|---|---|
| Backend | PHP 8.3, Laravel 12, домены в `app/Domain/{Content,Learning,Telegram,Twa,Administration}` | ✅ стабильно |
| Админка | Filament 5, роли `admin` / `teacher` (spatie/permission), 2FA для admin | ✅ |
| Бот | `irazasyed/telegram-bot-sdk` за контрактом `TelegramClient`, webhook → очередь `high` | ✅ |
| TWA | Vue 3 + Pinia + Tailwind, 5 экранов (landing, training, finished, exam, exam-result) | ✅ минимально |
| SRS | SM-2 (`SpacedRepetitionEngine`), `CardPicker` | ⚠️ см. 3.2 |
| Инфраструктура | Docker Compose prod (app, queue, scheduler, nginx, certbot, postgres, redis), spatie/backup, GitHub Actions | ✅ |
| Наблюдаемость | только логи и `/up` из коробки Laravel | ❌ |

### 1.2 Пользовательские сценарии, которые реально работают

1. Админ создаёт учителя, привязывает Telegram ID, активирует группу, которую бот поймал через `my_chat_member`.
2. Админ импортирует урок JSON (stage → lesson → words).
3. Учитель в группе: `/start_training [stage lesson]` (или выбор урока кнопками), `/start_exam`, `/close_exam`, `/stats` (в ЛС).
4. Студент жмёт кнопку → TWA → initData HMAC → JWT 15 мин → карточки с 3 оценками / экзамен MCQ с серверным таймером.
5. По окончании экзамена — лидерборд в группу (идемпотентно, `leaderboard_posted_at`).
6. Ежедневно в 18:00 UTC — напоминание студенту в ЛС, если ≥ 5 слов к повторению.

### 1.3 Сильные стороны (их надо сохранить)

- **Нулевое трение для студента:** нет регистрации, нет установки приложения — это главный конкурентный козырь против Quizlet/Anki/Duolingo в B2B.
- **Безопасность выше среднего для MVP:** корректная валидация initData (`hash_equals`, ручной парсинг без `parse_str`, проверка `auth_date` и future skew), JWT с проверкой issuer и отзывом при деактивации группы, серверный таймер экзамена, защита от двойного ответа на уровне БД, 2FA с одноразовыми recovery-кодами под `FOR UPDATE`, IP allowlist и секрет вебхука, маскирование PII в логах, CSP/HSTS.
- **Конкурентность продумана:** частичные unique-индексы на открытые сессии, `lockForUpdate` в ответах экзамена, идемпотентная публикация лидерборда.
- **Чистые границы:** Telegram SDK за адаптером, бизнес-логика в `Domain/*/Services`, `PanelDataScope` для учителя.
- **Процесс:** Pint + Larastan 8 + Pest в CI, мульти-агентный workflow описан в `CLAUDE.md`.

## 3. Продуктовые проблемы текущего MVP

### 3.1 🔴 Блокеры пилота (исправить в первую очередь)

1. **Напоминания студентам, скорее всего, не доходят.**
   Бот может написать в ЛС только тому, кто сам открыл с ним диалог. Студенты из группы этого не делают, а `/start` в ЛС отвечает студенту «аккаунт не привязан к учителю, попросите админа…» (`StartCommandHandler`) — это отпугивает. `SendReviewReminderJob` не обрабатывает 403 `bot can't initiate conversation`: лог не пишется, задание падает и ставится заново каждый день.
   **Что сделать:**
   - `/start` в ЛС для студента: приветствие, «включить напоминания», deep-link `t.me/<bot>?start=remind_<group>`; кнопка «Включить напоминания» в TWA после первой тренировки.
   - Поле `learners.can_dm` / `dm_blocked_at`; при 403 — пометить и не слать.
   - Альтернатива для тех, кто не дал доступ: еженедельная сводка в группе («5 человек не повторяли слова 3 дня») — мягкое социальное давление.
   - Метрика «доля студентов с включёнными напоминаниями» на дашборде учителя.

2. **Время рассылки 18:00 UTC = 23:00 в Ташкенте.** `app.timezone = UTC`, расписание `dailyAt('18:00')`.
   **Что сделать:** `timezone` у организации/группы (по умолчанию `Asia/Tashkent`), запуск рассылки каждые 15 минут с выборкой «у кого сейчас локальные 18:00–18:15», позже — персональное время (выбор в TWA).

3. **Кнопка «Средне» постепенно портит интервалы.** TWA отправляет оценки 2/3/5. По формуле SM-2 оценка 3 *уменьшает* EF (−0.14), 2 сбрасывает повторения и уменьшает EF на 0.32. Студент, который честно жмёт «Средне», через несколько повторений упирается в EF = 1.30 («ease hell»): интервалы растут медленно, нагрузка повторениями растёт, мотивация падает.
   **Что сделать (минимум):** перемаппить кнопки на 3 → 4 («Средне» = «вспомнил с усилием» без штрафа EF) — решение для `architect`, т.к. это алгоритм. **Среднесрочно:** перейти на FSRS (см. 4.1).

4. **«Трудное» слово не возвращается в той же сессии.** При q < 3 интервал = 1 день, карточка исчезает до завтра. В Anki/Quizlet слово, которое ты не вспомнил, показывается ещё раз через 1–10 минут — это ключ к запоминанию.
   **Что сделать:** learning steps (например, 1 мин и 10 мин) внутри сессии до перевода в «повторение через день».

5. **Экзамен легко списать.** Все студенты получают одинаковый порядок вопросов **и одинаковый порядок вариантов** (`ExamQuestionBuilder` формирует набор один раз на сессию). В групповом чате достаточно написать «3 — B».
   **Что сделать:** детерминированно перемешивать порядок вопросов и вариантов per-student (seed = `hash(session_id, student_id)`), `correct_index` вычислять на сервере в момент выдачи. Заодно убрать заглушки `— (filler #N)`, которые подсказывают ответ: при нехватке дистракторов брать слова из глобальной библиотеки той же части речи.

### 3.2 🟠 UX-пробелы

- **Нет «домашнего экрана» студента.** `LandingView` говорит «откройте тренировку через кнопку в группе». Студент не может сам открыть приложение и повторить всё, что пора, по всем урокам. `GET /api/twa/me` уже есть — нужен экран «Сегодня: 23 слова к повторению · серия 5 дней · [Начать]» и тренировка «все due-слова» без привязки к сессии учителя.
- **Только одно направление:** EN → перевод. Нет RU→EN, ввода с клавиатуры, аудирования («услышал — выбери»), что важно для реальной памяти.
- **Нет обратной связи после экзамена:** только счёт и ранг. Нужен разбор ошибок и кнопка «добавить ошибки в повторение».
- **Нет прогресса для учителя внутри Telegram,** кроме `/stats`. Учителю нужно видеть «кто не занимался» и «самые трудные слова группы» за 2 нажатия, без входа в админку.
- **Импорт только JSON.** Учитель реально живёт в Excel/Google Sheets. Нужен импорт CSV/XLSX и вставка списком «word — перевод».

## 4. Рекомендации по улучшению продукта (ядро обучения)

### 4.1 Алгоритм повторений: SM-2 → FSRS

FSRS (Free Spaced Repetition Scheduler) — современный алгоритм, используемый в Anki с 2023 года; на тех же данных даёт меньше повторений при той же запоминаемости и хорошо работает с 3–4 кнопками.

План (задача для `architect`, реализация — `coder`):
1. Ввести интерфейс `SchedulerAlgorithm` с методом `schedule(state, rating, now): state`; текущий SM-2 — первая реализация.
2. Добавить в `word_repetitions` поля `stability`, `difficulty`, `state` (new/learning/review/relearning), `lapses`; сохранить SM-2 поля для отката.
3. FSRS с параметрами по умолчанию; флаг алгоритма на уровне организации (A/B-тест на реальных группах).
4. Позже — оптимизация параметров FSRS по истории `training_reviews` каждой организации (ночной job).

### 4.2 Новые типы упражнений (по возрастанию сложности)

| Упражнение | Ценность | Сложность |
|---|---|---|
| Обратная карточка (RU → EN) | высокая | низкая |
| Аудио-карточка: слушаешь → выбираешь/пишешь слово | высокая | низкая (TTS уже есть) |
| Ввод слова с клавиатуры (spelling) с допуском опечаток (Levenshtein) | высокая | средняя |
| Gap-fill по `example` (слово скрыто в предложении) | высокая | низкая — примеры уже в БД |
| Matching (5 пар за раз) — для экзамена-разминки | средняя | средняя |
| AI-проверка своего предложения со словом | высокая для Pro | средняя (LLM API) |
| Произношение (запись → STT → сравнение) | высокая, «вау» | высокая |

### 4.3 Мотивация и удержание

- **Серия (streak) и дневная цель** — самый дешёвый и сильный рычаг удержания.
- **Групповые механики** (сильная сторона Telegram): недельный рейтинг группы по выученным словам, автоматический пост «Итоги недели» в группу, «вызов группы» (группа вместе выучила 500 слов).
- **Отчёт родителям** (для детских центров — киллер-фича для продаж): еженедельное сообщение родителю в Telegram — сколько занимался ребёнок, оценка экзамена. Центры за это платят, потому что это их маркетинг.
- **Сертификат/бейдж за уровень** (PDF/картинка для шеринга) — органический рост.

## 5. Архитектура мультиарендности (фундамент SaaS)

### 5.1 Выбор модели

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| Отдельная БД на клиента | максимальная изоляция | дорого в эксплуатации, миграции × N | ❌ рано |
| Отдельная схема Postgres на клиента | хорошая изоляция | сложнее аналитика и пул соединений | 🟡 для Enterprise позже |
| **Одна БД, `organization_id` + global scope + Postgres RLS** | дёшево, просто, аналитика по всем | нужна дисциплина и тесты изоляции | ✅ **рекомендуется** |

Пакет: можно `stancl/tenancy` в single-database режиме, но для этого проекта проще и прозрачнее свой трейт `BelongsToOrganization` (global scope + автозаполнение `organization_id`) — **новые зависимости согласовать с владельцем** (правило `CLAUDE.md`).

### 5.2 Изменения схемы (черновик для `architect`)

```
organizations          id, name, slug, timezone, locale, plan, status, trial_ends_at, settings jsonb
organization_users     organization_id, user_id, role (owner|admin|teacher)
telegram_bots          id, organization_id NULL (NULL = общий бот платформы), username,
                       token (encrypted), webhook_secret (encrypted), status
learners               id, telegram_user_id UNIQUE, first_name, username, language_code,
                       timezone, can_dm, dm_blocked_at, reminder_time
enrollments            id, organization_id, learner_id, telegram_group_id, status, joined_at
courses / decks        id, organization_id NULL (NULL = общая библиотека), visibility, source
                       (stages/lessons → привязать к course; words остаются)
assignments            id, organization_id, telegram_group_id, lesson_id, type (training|homework|exam),
                       due_at, created_by
subscriptions          id, organization_id, plan, status, period_start, period_end, provider, provider_ref
usage_counters         organization_id, period, active_learners, ai_requests, tts_seconds
events                 id, organization_id, actor_type, actor_id, name, props jsonb, created_at
```

Ключевые правила:
- `organization_id` NOT NULL во всех таблицах с данными клиента (`telegram_groups`, `training_*`, `exam_*`, `word_repetitions` через enrollment/learner, `audit_logs`, `notifications_log`).
- Global scope включён по умолчанию; выключение — только явно в системных job'ах.
- **Postgres Row-Level Security** как второй рубеж: `SET app.current_org = ?` в начале запроса/джоба, политика `USING (organization_id = current_setting('app.current_org')::bigint)`. Даже забытый scope не даст утечки.
- Pest-тесты изоляции: на каждый Filament-ресурс и API-эндпоинт — «пользователь орг. A не видит/не меняет данные орг. B» (IDOR-тесты).
- Миграция существующих данных: создать организацию «Default», проставить её всем строкам, затем `NOT NULL`.

### 5.3 Боты: общий бот + white-label

- **Старт:** один общий бот платформы (`@LexiFlowBot`). Группа привязывается к организации кодом приглашения: владелец центра в админке получает `/link ABC123`, отправляет в группе — группа становится `active` в его организации. Это заменяет ручную активацию админом платформы.
- **Тариф Business+:** свой бот центра (`@MyCenterEnglishBot`) — токен шифруется (`encrypted` cast + отдельный ключ), webhook `/telegram/webhook/{bot_id}/{secret}`, `InitDataValidator` выбирает токен по боту (initData подписан токеном того бота, который открыл Mini App). Брендинг TWA: логотип, цвета, название.

### 5.4 Роли и доступы

`owner` (биллинг, удаление организации) → `admin` (учителя, группы, контент) → `teacher` (свои группы, свой контент) → `learner`. Суперадмин платформы — отдельный guard/панель Filament (`/platform`), с impersonation и обязательной записью в аудит.

## 6. Стратегия SaaS: рынок, позиционирование, монетизация

### 6.1 Позиционирование

> **«LexiFlow — онлайн-класс для вашего учебного центра прямо в Telegram. Домашка по словам, экзамены и отчёты родителям — без установки приложений.»**

Почему B2B первым:
- В Узбекистане и Центральной Азии Telegram — основной мессенджер, а учебные центры уже ведут группы в Telegram. Продукт встраивается в существующую привычку.
- Центр платит за **удержание учеников и видимость результата** (отчёты родителям, рейтинги), а не за «ещё одно приложение со словами».
- Один продажный контакт = 50–500 активных учеников. CAC ниже, чем в B2C.
- B2C-флэшкарты — красный океан (Duolingo, Anki, Quizlet, бесплатные боты).

### 6.2 Сегменты (в порядке приоритета)

1. **Языковые центры (10–300 учеников)** — основной.
2. **Репетиторы-одиночки (5–40 учеников)** — self-serve, дешёвый тариф, канал виральности (каждый репетитор приводит учеников).
3. **Школы/частные школы** — позже, длинный цикл продаж.
4. **B2C-одиночки** — как freemium-воронка с общей библиотекой (IELTS, Top-3000), не как основной доход.

### 6.3 Тарифы (гипотеза — проверить на 5–10 интервью с центрами)

| Тариф | Для кого | Что входит | Ориентир цены |
|---|---|---|---|
| **Free** | репетитор на пробу | 1 учитель, 1 группа, до 15 учеников, общая библиотека, тренировки | 0 |
| **Tutor** | репетитор | до 40 учеников, свой контент, экзамены, отчёты | ~$5–8 / мес |
| **Center** | центр | без лимита групп, оплата за **активного ученика в месяц**, отчёты родителям, аналитика, несколько учителей | ~$0.5–1 за активного ученика / мес |
| **Business** | сеть центров | white-label бот, брендинг TWA, API, приоритетная поддержка, SLA | индивидуально |
| **AI add-on** | любой | AI-генерация уроков и упражнений, проверка предложений, произношение | за пакеты запросов |

Принципы:
- Оплата за **активного** ученика (занимался хотя бы раз за месяц) — честно для центра и мотивирует вас повышать активацию.
- 14-дневный trial тарифа Center без карты.
- Годовая оплата со скидкой (центрам удобно платить по счёту).

### 6.4 Оплата — важная поправка к документу 10

- По правилам Telegram оплата **цифровых товаров и услуг внутри бота/Mini App** должна идти через **Telegram Stars**. Для B2C-подписок внутри бота закладывайте Stars (Bot API `sendInvoice` с валютой `XTR`, подписки через `createInvoiceLink` с `subscription_period`). Stripe/ЮKassa через Telegram Payments для цифровых подписок не подойдут. *Перед запуском перепроверить актуальную редакцию правил.*
- **B2B (центры)** платят вне Telegram: веб-кабинет + **Payme / Click / Uzum** для Узбекистана, счёт-фактура и банковский перевод для юрлиц; Stripe/Paddle — для международных клиентов.
- Архитектура: интерфейс `BillingProvider` (`PaymeProvider`, `ClickProvider`, `TelegramStarsProvider`, `StripeProvider`), единая таблица `subscriptions`, идемпотентная обработка webhook'ов (ключ — `provider_ref` события), состояние `past_due` + grace period 7 дней, затем read-only режим (данные не удаляются).
- Проверка подписи webhook'ов каждого провайдера, allowlist IP, повторная обработка без двойного зачисления — **задача для `architect`** (идемпотентность и деньги).

### 6.5 Соответствие законодательству (проверить с юристом)

- **Узбекистан, закон «О персональных данных»:** с 2021 года персональные данные граждан РУз должны обрабатываться и храниться на серверах на территории Узбекистана (локализация). Для B2B-клиентов из Узбекистана это аргумент за хостинг в UZ-дата-центре (или гибрид) — и одновременно **конкурентное преимущество** перед зарубежными сервисами.
- Дети: многие центры работают с несовершеннолетними → согласие родителей, минимизация данных (сейчас хранится только Telegram-профиль — это хорошо).
- Договор-оферта, политика конфиденциальности, DPA для центров, экспорт и удаление данных организации (уже в backlog: «Экспорт данных студента»).

## 8. Безопасность при переходе к SaaS

Текущая база хорошая, но у SaaS другая модель угроз: главный риск — **утечка данных между арендаторами** и компрометация токенов ботов клиентов.

| Угроза | Мера |
|---|---|
| IDOR между организациями | global scope + Postgres RLS + автоматические тесты изоляции на каждый ресурс/эндпоинт |
| Утечка токенов white-label ботов | шифрование на уровне приложения отдельным ключом (не `APP_KEY`), ротация, токены никогда не попадают в логи/аудит/ответы API, доступ только у job'ов отправки |
| Захват аккаунта владельца центра | 2FA обязательна для `owner`/`admin` (сейчас только для `admin`), уведомление о входе с нового устройства, сессии с device list |
| Злоупотребление общим ботом (спам через рассылки) | per-organization rate limit и квоты сообщений, лимиты в тарифе |
| Replay initData | сократить `TWA_INIT_DATA_MAX_AGE` с 24 ч до ~1 ч (Mini App каждый раз получает свежий initData при открытии) |
| JWT без отзыва | добавить `jti` и короткий denylist в Redis при выходе/блокировке; `aud` = id бота для white-label |
| Webhook биллинга | проверка подписи, идемпотентность, allowlist IP провайдера |
| Prompt injection (AI-фичи) | пользовательский текст только как данные, жёсткая схема вывода, лимиты и модерация публичного контента |
| Супер-админ платформы | отдельная панель, impersonation только с аудитом и причиной, IP allowlist |

Процессы: регулярный `composer audit`/`npm audit` (уже в CI), Dependabot, SAST (Larastan уже есть; добавить Semgrep с правилами PHP/Laravel), DAST (OWASP ZAP baseline на staging в CI), внешний пентест перед первым крупным клиентом, страница `security.txt` и простая программа responsible disclosure.

## 9. AI-фичи: где они действительно окупаются

Не «AI ради AI», а снятие самой большой боли учителя — **подготовки контента**.

1. **Генерация урока из текста/темы:** учитель вставляет текст (или пишет «Food, A2, 20 слов») → получает черновик урока: слово, перевод на ru/uz, транскрипция, пример уровня группы → правит и публикует. Экономит учителю часы в неделю — это и есть аргумент для оплаты.
2. **Автодистракторы для экзамена** правдоподобные (та же часть речи, похожий смысл) — повышает качество экзамена.
3. **Проверка предложения со словом** (AI add-on): короткий фидбек на языке ученика.
4. **Недельный AI-отчёт учителю:** «у группы проблемы с phrasal verbs, вот 10 слов на повтор».

Технически: очередь `ai` с отдельными воркерами, кэш результатов по хешу запроса, квоты в `usage_counters`, модель уровня Claude Haiku 5.5 для массовых дешёвых задач и Sonnet 5.5 для генерации уроков; строгий JSON-вывод с валидацией через тот же `VocabularyImporter`.

## 11. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Зависимость от одной платформы (Telegram: блокировки, изменение правил оплаты) | средняя | веб-версия как запасной канал; данные и аккаунты не завязаны только на Telegram |
| Центры не готовы платить за «карточки» | средняя | продавать результат (удержание учеников, отчёты родителям), а не карточки; оплата за активного ученика |
| Учителя не меняют привычки | высокая | онбординг за 10 минут, готовая библиотека, AI-генерация уроков, обучение в формате видео/вебинара |

| Один разработчик — bus factor | высокая | документация уже сильная; поддерживать `docs/` в актуальном виде, мульти-агентный процесс из `CLAUDE.md` |
