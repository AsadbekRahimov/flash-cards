# Настройка озвучки: Google Cloud TTS и Cloudflare R2

> **Основной сервис озвучки теперь Deepgram (решение владельца 25.11.2026):** инструкция — [37_DEEPGRAM_TTS_SETUP_RU.md](37_DEEPGRAM_TTS_SETUP_RU.md). Google Cloud TTS (часть A, переменные `GOOGLE_TTS_*`, `TTS_MONTHLY_CHAR_LIMIT`) остаётся рабочей **альтернативой** (`TTS_DRIVER=google`). Части B (R2), C2 (диск и адрес файлов), C3 (воркер) и справочник команд C6 действуют и для Deepgram.

> **Будет изменено.** Владелец решил (25.11.2026): озвучка отдаётся с основного домена — `https://основной-домен/audio/…`, без отдельного `audio.ваш-домен`. План — [31_COMPETITION_PLAN_RU.md](31_COMPETITION_PLAN_RU.md) §5д. До выполнения задач U0–U4 инструкция ниже описывает текущее поведение.

> **Уже сделано (U2, диск `public`):** файлы на вашем сервере открываются по адресу `https://основной-домен/audio/<хеш>.mp3` (переменная `TTS_PUBLIC_DISK_AUDIO_URL` в C2). Старый адрес `/storage/audio/<хеш>.mp3` продолжает работать. Раздача файлов R2 с основного домена — ещё не сделана.

Пошаговое руководство для владельца. Как устроен код — `docs/26_AUDIO_TTS_PLAN_RU.md`. Имена переменных и команд ниже сверены с кодом (`config/twa.php`, `config/filesystems.php`, `.env.example`, `docker-compose.prod.yml`, `docker-compose.coolify.yml`, команды `audio:*`).

> Названия пунктов меню в консолях Google и Cloudflare меняются; если пункт называется иначе, ищите по смыслу. Цены и квоты проверены по официальным страницам 20.11.2026.

## Что получится

```
новое слово / импорт / правка текста или примера ──► очередь tts ──► Google Cloud TTS ──► mp3 ──► бакет R2
ученик открывает карточку ──► https://audio.ваш-домен/audio/<хеш>.mp3 ──► кэш Cloudflare ──► R2
```

Google вызывается один раз на каждый текст и только из заданий очереди. Ученики к Google не обращаются, синтеза «по запросу ученика» нет: если у слова ещё нет файла, Mini App говорит голосом телефона, а без него молчит.

Озвучиваются слова курсов, их примеры и фразы диктантов практики. У примера озвучивается только **основной** пример слова (поле «Пример» слова, `words.example`); дополнительные примеры (вкладка примеров слова, показываются по очереди после выпуска карточки) — без звука. Кнопка озвучки примера в Mini App появляется только когда файл готов: голосом телефона пример не читается. Свои колоды учеников Google **не** озвучивает (голос телефона).

## Часть A. Google Cloud

### A1. Проект и оплата

1. Откройте `console.cloud.google.com` и войдите рабочим аккаунтом Google (не личным: доступ к проекту потом можно передать).
2. Создайте проект: список проектов вверху → **New project** → имя, например `lexiflow-tts`.
3. **Billing** → привяжите платёжный профиль с картой. Без него API не включится, даже если вы остаётесь в бесплатном объёме.
   - Примет ли Google карту из Узбекистана — не проверено. Если не примет, используйте карту другой страны или партнёра-реселлера Google Cloud.
   - Новым аккаунтам Google даёт пробный кредит (на 20.11.2026 — $300); он не обязателен.

### A2. Включить API

1. **APIs & Services → Library**.
2. Найдите **Cloud Text-to-Speech API** → **Enable**.

### A3. Сервисный аккаунт и ключ

Приложение входит в Google не вашим паролем, а отдельным техническим аккаунтом.

1. **IAM & Admin → Service Accounts → Create service account**.
2. Имя: `lexiflow-tts`. Ролей на проект **не давайте** — для вызова TTS из своего же проекта они, как правило, не нужны. Если задания падают с `tts_forbidden` (Google ответил `403 PERMISSION_DENIED`), добавьте роль **Service Usage Consumer** (`roles/serviceusage.serviceUsageConsumer`) и больше ничего.
3. Откройте созданный аккаунт → **Keys → Add key → Create new key → JSON**. Скачается файл `lexiflow-tts-….json`.
4. Этот файл — пароль. Правила:
   - не кладите его в репозиторий, в чат, в почту;
   - приложение принимает ключ **только файлом**: путь к файлу задаётся переменной, а содержимое JSON в переменную окружения класть нельзя (оно попало бы в кэш настроек `bootstrap/cache/config.php` и в дампы окружения) — такой вариант код не поддерживает;
   - как положить файл на сервер и какие у него права — часть C, шаг C1;
   - при подозрении на утечку — ротация ключа (C10).

Если в организации Google включён запрет на ключи сервисных аккаунтов (`iam.disableServiceAccountKeyCreation`), кнопка создания ключа будет недоступна — запрет снимается в **Organization Policies** администратором организации.

### A4. Проверка с вашего компьютера (необязательно)

Нужен установленный `gcloud`.

```bash
gcloud auth activate-service-account --key-file=lexiflow-tts-XXXX.json
```

```bash
curl -s -X POST "https://texttospeech.googleapis.com/v1/text:synthesize" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{"input":{"text":"surname"},"voice":{"languageCode":"en-US","name":"en-US-Neural2-F"},"audioConfig":{"audioEncoding":"MP3"}}' \
  | python3 -c "import sys,json,base64; open('test.mp3','wb').write(base64.b64decode(json.load(sys.stdin)['audioContent']))"
```

Появился `test.mp3` и он звучит — Google настроен. Сам сервер входит в Google иначе (подписывает токен ключом сам, без `gcloud`), поэтому настоящая проверка — команда `audio:sample` на сервере (C4).

### A5. Выбор голоса

| Семейство | Цена за 1 млн символов | Бесплатно в месяц | Когда брать |
|---|---|---|---|
| Chirp 3 HD (`en-US-Chirp3-HD-…`) | $30 | 1 млн | самый естественный; проверить на одиночных словах |
| Neural2 (`en-US-Neural2-…`) | $16 | 1 млн | ровный, предсказуемый на коротких словах |
| WaveNet / Standard | $4 | 4 млн | заметно проще по звучанию |

- **Голос должен быть голосом Google.** Приложение принимает имя вида `язык-СТРАНА-семейство-имя` из семейств `Neural2`, `Chirp3-HD`, `Chirp-HD`, `Wavenet`, `Standard`, `Studio`, `News`, `Polyglot`, `Casual` — например `en-US-Neural2-F`, `en-US-Chirp3-HD-Charon`, `en-US-Wavenet-D`, `en-GB-Neural2-A`. Любое другое имя Google не отправляется: каждое задание сразу завершается с `tts_voice_unsupported`.
- **По умолчанию `TTS_VOICE=en-US-AriaNeural`** — это имя голоса edge-tts (старый локальный сервис), а не Google. С `TTS_DRIVER=google` его **обязательно** нужно поменять.
- Весь первый прогон — ≈ 308 тыс. символов (слова 37 тыс. + диктанты 51 тыс. + примеры 220 тыс.) из 900 тыс. месячного предела приложения; это меньше бесплатного миллиона у любого семейства.
- Послушать голоса: страница Cloud Text-to-Speech в консоли или демо на `cloud.google.com/text-to-speech`. Окончательно выбирайте по `audio:sample` (C4): там именно наши трудные слова.
- Список имён: `curl -H "Authorization: Bearer $(gcloud auth print-access-token)" "https://texttospeech.googleapis.com/v1/voices?languageCode=en-US"`.
- Американский (`en-US`) или британский (`en-GB`) вариант — решите до массового прогона: транскрипции в курсах американские (`/ˈsɜrneɪm/`). Смена голоса потом — это полный повторный прогон (C9).
- Документация Google на 20.11.2026 противоречива насчёт SSML и скорости речи у Chirp 3 HD; приложение их не использует (запрос одинаковый для всех семейств: MP3, 24 000 Гц), так что это не мешает.

### A6. Квоты

**APIs & Services → Cloud Text-to-Speech API → Quotas**. По умолчанию: 200 запросов в минуту для Chirp 3, 1 000 для Neural2, до 5 000 байт текста в запросе. Приложение само держит темп ниже квоты (`TTS_RATE_PER_MINUTE`, по умолчанию 150 в минуту на все воркеры вместе); повышать ничего не нужно.

### A7. Защита от неожиданного счёта

1. **Billing → Budgets & alerts → Create budget**.
2. Область: проект `lexiflow-tts`. Сумма: например $5 в месяц.
3. Оповещения на 50 %, 90 %, 100 % — на вашу почту.

Бюджет **только предупреждает**, сам он расходы не останавливает. Останавливает их ограничитель в приложении (`TTS_MONTHLY_CHAR_LIMIT`, по умолчанию 900 000 символов в месяц — ниже бесплатного миллиона) и, в крайнем случае, отключение API или ключа в консоли.

## Часть B. Cloudflare R2

Сайт должен быть подключён к Cloudflare (`docs/23_CLOUDFLARE_RU.md`). R2 не обязателен: без него файлы лежат и раздаются с вашего сервера по адресу `https://ваш-домен/audio/<хеш>.mp3` (`TTS_AUDIO_DISK=public`, по умолчанию). R2 разгружает сервер и даёт кэш Cloudflare.

### B1. Бакет

1. Cloudflare → **R2 Object Storage → Create bucket**.
2. Имя: `lexiflow-audio`. Расположение: Automatic. Класс хранения: **Standard** (бесплатный объём действует только для него).
3. Это **отдельный** бакет. Бакет резервных копий остаётся закрытым и сюда не подключается.

### B2. Свой домен для бакета

1. Бакет → **Settings → Public access → Custom Domains → Connect Domain**.
2. Домен: `audio.ваш-домен` (поддомен зоны, которая уже в Cloudflare). Cloudflare сам создаст DNS-запись и сертификат.
3. Адрес вида `…r2.dev` **не включайте**: у него нет кэша и есть ограничение скорости, он для разработки.

Этот адрес потом станет переменной `AUDIO_PUBLIC_URL` (C2). Он **обязателен** и должен начинаться с `https://`:
- из него приложение строит адреса файлов для учеников; без него адрес получился бы адресом API бакета, который не публичен;
- из него nginx берёт домен для CSP Mini App (`media-src`); адрес не `https://хост[:порт][/путь]` — контейнер nginx не запустится, в логе будет `AUDIO_PUBLIC_URL must be https://host[:port][/path]`.

### B3. Кэш

Файлы никогда не меняются (имя построено от содержимого, объект записывается с `Cache-Control: public, max-age=31536000, immutable`), поэтому кэш — максимальный.

1. **Caching → Cache Rules → Create rule**.
2. Условие: `Hostname equals audio.ваш-домен`.
3. Действие: **Eligible for cache**, Edge TTL — 1 год, Browser TTL — 1 год.

Попадания в кэш Cloudflare не считаются чтениями R2.

**CORS на бакете не настраивайте** (и Transform Rules для `Access-Control-Allow-Origin` тоже не нужны): Mini App не читает файлы озвучки через `fetch`, а играет их в `<audio>` — браузер не делает для этого CORS-запросов, и токен ученика на домен озвучки не уходит (docs/26 §9.9). Если CORS уже настроен — он не мешает, но и не нужен.

### B4. Ключ доступа для приложения

1. **R2 → Manage R2 API Tokens → Create API token**.
2. Права: **Object Read & Write**, область — **только бакет `lexiflow-audio`**.
3. Сохраните `Access Key ID`, `Secret Access Key` и адрес `https://<account-id>.r2.cloudflarestorage.com` (без имени бакета). Секрет показывается один раз.

Не используйте ключ резервных копий (`BACKUP_*`): у него доступ к дампам базы.

### B5. Сколько это стоит

| Что | Цена | Бесплатно в месяц | У вас |
|---|---|---|---|
| Хранение | $0,015 за ГБ | 10 ГБ | < 0,3 ГБ |
| Отдача данных | $0 | — | — |
| Чтения (класс B) | $0,36 за 1 млн | 10 млн | ≈ 5 млн при 3 000 учеников без кэша |
| Записи (класс A) | $4,50 за 1 млн | 1 млн | ≈ 12 тыс. разово |

## Часть C. Приложение

Команды ниже — для Docker (`docker-compose.prod.yml`): `docker compose -f docker-compose.prod.yml exec app php artisan …`. В Coolify те же команды запускаются в контейнере `lf-app` (Terminal в Coolify). Без Docker — просто `php artisan …` в папке проекта. Ниже для краткости — `php artisan …`.

### C1. Ключ Google на сервере

Файл ключа лежит на хосте **вне папки проекта** и подключается в контейнеры только для чтения:

| Где | Что |
|---|---|
| на хосте | любой путь, его вы пишете в `GOOGLE_TTS_KEY_FILE` (в `.env` рядом с `docker-compose.prod.yml`; в Coolify — в переменных приложения) |
| в контейнере | всегда `/run/secrets/google-tts.json` — это значение `GOOGLE_TTS_CREDENTIALS` |
| в каких контейнерах | `app` (для `audio:sample`), `queue-low` (озвучивает), `scheduler` (ночная сверка проверяет ключ); в Coolify — `lf-app`, `lf-queue-low`, `lf-scheduler` |

Внутри контейнеров приложение работает под пользователем с UID/GID `1000` (аргументы сборки образа `UID`/`GID`). Файл должен читаться этим пользователем и больше никем:

```bash
sudo mkdir -p /etc/lexiflow
sudo install -m 0440 -o root -g 1000 lexiflow-tts-XXXX.json /etc/lexiflow/google-tts.json
```

(`0400` с владельцем `1000` тоже подходит.) Если `GOOGLE_TTS_KEY_FILE` не задан, в контейнер подключается пустой `/dev/null`, и с `TTS_DRIVER=google` каждое задание завершится с `tts_credentials_invalid`.

Без Docker: положите файл так же вне проекта, права `0400`/`0440` на пользователя воркера очереди (например `www-data`), и укажите этот путь прямо в `GOOGLE_TTS_CREDENTIALS`; `GOOGLE_TTS_KEY_FILE` не нужен.

Приложение проверяет файл при первом вызове: это обычный файл до 16 КБ, JSON, `"type": "service_account"`, правильные `client_email`, `private_key_id` и RSA-ключ `private_key`. Любая ошибка — `tts_credentials_invalid` без подробностей (текст файла никуда не пишется).

### C2. Переменные

Все переменные озвучки (полный список с комментариями — в `.env.example`):

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `TTS_DRIVER` | пусто | `deepgram` — Deepgram Aura-2, основной (docs/37); `google` — Google Cloud TTS; `http` — старый edge-tts-совместимый сервис `TTS_SERVICE_URL` (для локальной разработки); `null` — озвучки нет. **Пусто = `http`, если задан `TTS_SERVICE_URL`, иначе `null`.** Опечатка (не `deepgram`/`google`/`http`/`null`) сайт не ломает: синтез не работает, `/health/ready` показывает `"tts": "degraded"`, `audio:sample` и `audio:reconcile` пишут об этом |
| `TTS_SERVICE_URL` | `http://tts:8000` в `.env.example` | только для `http` |
| `TTS_SERVICE_TIMEOUT` | `8` | только для `http`, секунд |
| `TTS_VOICE` | `en-US-AriaNeural` | голос; для `google` — обязательно голос Google (A5) |
| `TTS_AUDIO_VERSION` | `1` | входит в имя файла; поднять = переозвучить всё (C9) |
| `TTS_AUDIO_DISK` | `public` | где лежат файлы слов: `public` — этот сервер (адрес `/audio/<хеш>.mp3` основного домена), `audio` — R2 |
| `TTS_PUBLIC_DISK_AUDIO_URL` | `APP_URL` | только для `public`: начало адреса файла, адрес = это значение + `/audio/<хеш>.mp3`. Файл отдаёт nginx (`location /audio/`); старый адрес `/storage/audio/` nginx тоже отдаёт. `${APP_URL}/storage` (или пустая строка) возвращает старые адреса. Без nginx (`php artisan serve`) — `php artisan storage:link` |
| `GOOGLE_TTS_CREDENTIALS` | пусто | путь к файлу ключа **внутри контейнера**: в Docker всегда `/run/secrets/google-tts.json`. Пусто — `tts_service_not_configured` |
| `GOOGLE_TTS_KEY_FILE` | пусто | только Docker: путь к файлу ключа **на хосте** (C1) |
| `GOOGLE_TTS_TIMEOUT` | `20` | секунд ждать ответа Google (соединение — 5 с, не настраивается) |
| `TTS_RATE_PER_MINUTE` | `150` | запросов к Google в минуту на все воркеры вместе; задание ждёт до 30 с, потом `tts_rate_limited` и повтор |
| `TTS_MONTHLY_CHAR_LIMIT` | `900000` | символов в месяц; `0` — синтез запрещён. Месяц считается **по тихоокеанскому времени** (как счета Google): новый месяц начинается в 08:00 UTC первого числа (летом — в 07:00) |
| `TTS_QUEUE_ATTENTION_SIZE` | `3000` | строка «Очередь озвучки» в «Требуют внимания», когда в очереди `tts` больше заданий |
| `AUDIO_ACCESS_KEY_ID`, `AUDIO_SECRET_ACCESS_KEY` | пусто | ключ R2 из B4 |
| `AUDIO_DEFAULT_REGION` | `auto` | для R2 всегда `auto` |
| `AUDIO_BUCKET` | пусто | `lexiflow-audio` |
| `AUDIO_ENDPOINT` | `https://<account-id>.r2.cloudflarestorage.com` | адрес из B4, без имени бакета |
| `AUDIO_PUBLIC_URL` | пусто | свой домен бакета из B2, `https://`, без `/` в конце. Обязателен при `TTS_AUDIO_DISK=audio` |
| `AUDIO_USE_PATH_STYLE_ENDPOINT` | `false` | для R2 не трогать |

Пример для Google + R2:

```dotenv
TTS_DRIVER=google
TTS_VOICE=en-US-Neural2-F
TTS_AUDIO_VERSION=1
GOOGLE_TTS_CREDENTIALS=/run/secrets/google-tts.json
GOOGLE_TTS_KEY_FILE=/etc/lexiflow/google-tts.json
TTS_MONTHLY_CHAR_LIMIT=900000

TTS_AUDIO_DISK=audio
AUDIO_ACCESS_KEY_ID=...
AUDIO_SECRET_ACCESS_KEY=...
AUDIO_BUCKET=lexiflow-audio
AUDIO_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
AUDIO_PUBLIC_URL=https://audio.ваш-домен
```

**Как применить правку `.env`.** В Docker контейнер при старте сам делает `config:cache`, поэтому достаточно пересоздать контейнеры: `docker compose -f docker-compose.prod.yml up -d` (сменился `GOOGLE_TTS_KEY_FILE` — пересоздадутся контейнеры с ключом). **После задания или смены `AUDIO_PUBLIC_URL` обязательно пересоздайте nginx** — домен попадает в CSP только при старте контейнера: `docker compose -f docker-compose.prod.yml up -d --force-recreate nginx` (в Coolify — передеплой, контейнер `lf-nginx`). Без этого Mini App не сможет играть файлы с домена озвучки (ошибка CSP). Без Docker: `php artisan config:cache` и `php artisan queue:restart`.

### C3. Воркер очереди

Задания озвучки идут в отдельную очередь `tts`. Её обслуживает воркер `low` с `--queue=low,tts`: сначала короткие задания `low`, озвучка — когда `low` пуст. Так массовый прогон не задерживает остальную работу.

- Docker: уже настроено в `docker-compose.prod.yml` (сервис `queue-low`) и `docker-compose.coolify.yml` (`lf-queue-low`).
- Без Docker (supervisor): в команде воркера `low` должно быть `--queue=low,tts` (docs/DEVOPS_GUIDE.md §10). Без `tts` в списке задания озвучки будут копиться и никто их не выполнит.

### C4. Порядок включения

Каждый шаг можно проверить до следующего; на любом шаге можно остановиться.

1. **Выкатить код с выключенной озвучкой.** В `.env` явно `TTS_DRIVER=null`. Внимание: пустой `TTS_DRIVER` при заданном `TTS_SERVICE_URL` (в `.env.example` он задан: `http://tts:8000`) означает драйвер `http`, а контейнера `tts` в продакшене нет — задания будут падать с `tts_service_failed`. С `null` новые слова и ночная сверка заданий не ставят.
2. **Настроить Google и R2** по частям A и B, положить ключ (C1).
3. **Задать переменные R2** (`AUDIO_*`, включая `AUDIO_PUBLIC_URL`) и **пересоздать nginx** (C2).
4. **Если на сервере уже есть файлы озвучки** (`TTS_AUDIO_DISK=public`, папка `storage/app/public/audio/` не пуста — адреса `/audio/…`, раньше `/storage/audio/…`) — перенести их в R2, пока сайт ещё раздаёт их с сервера:

   ```bash
   php artisan audio:migrate-disk --to=audio --dry-run   # только посчитать
   php artisan audio:migrate-disk --to=audio
   ```

   Если файлов нет — шаг пропустить.
5. **Переключить диск:** `TTS_AUDIO_DISK=audio`, пересоздать контейнеры. Новые файлы теперь пишутся в R2, адреса карточек ведут на `AUDIO_PUBLIC_URL`. Сессии практики и игры, открытые до переключения, до своего конца могут остаться без звука слов — это нормально.
6. **Задать Google:** `TTS_DRIVER=google`, `GOOGLE_TTS_CREDENTIALS=/run/secrets/google-tts.json`, `GOOGLE_TTS_KEY_FILE=…`, `TTS_VOICE=<голос Google>`; пересоздать контейнеры.
7. **Контрольный набор и прослушивание:**

   ```bash
   php artisan audio:sample
   ```

   Это первый настоящий вызов Google. Файлы ложатся в контейнер `app` в `storage/app/audio-samples/<голос>/`; скопировать к себе:

   ```bash
   docker compose -f docker-compose.prod.yml cp app:/var/www/html/storage/app/audio-samples ./audio-samples
   ```

   Послушайте. Не нравится — `php artisan audio:sample --voice=en-US-Chirp3-HD-Charon` (другой голос без правки `.env`), выберите и запишите его в `TTS_VOICE`. Ошибка — смотрите её код в C8.
8. **Пробный прогон одного курса** (проверяет запись в R2, которую `audio:sample` не трогает — он пишет файлы на сервер):

   ```bash
   php artisan audio:pregenerate <slug-курса>
   php artisan audio:coverage <slug-курса> --verify
   ```

   Подождите, пока очередь отработает, и откройте в браузере адрес любого файла (C5).
9. **Озвучить всё:**

   ```bash
   php artisan audio:pregenerate --all
   ```

   Команда ставит и слова, и примеры (только слова — `--only=words`, только примеры — `--only=examples`) и печатает по две строки на курс (`<slug>: queued N, already up to date M` и `<slug> examples: queued N, already up to date M`) — отсюда же список slug-ов для следующего шага. Первый прогон — ≈ 308 тыс. символов (слова 37 тыс., диктанты 51 тыс., примеры 220 тыс.) из 900 тыс. месячного предела. На 6,5 тыс. слов и диктантов при темпе ниже квоты — порядка часа, примеры — ещё 5 тыс. заданий (оценка). Пока очередь длиннее `TTS_QUEUE_ATTENTION_SIZE`, в `/admin` висит строка «Очередь озвучки» — во время массового прогона это нормально.
10. **Проверить покрытие по каждому курсу:**

    ```bash
    php artisan audio:coverage <slug-курса> --verify
    ```

11. **Проверить на телефоне** (Android и iOS): слово на карточке звучит с домена озвучки, у озвученного примера в панели ответа есть кнопка-динамик и она звучит, диктант практики, комната баттла-диктанта («Готов» открывается), «Караван» с заданием «послушай»; в Remote Debugging нет ошибок CSP и нет запросов `fetch` на домен озвучки.

**Примеры после выката кода с примерами.** Если слова уже озвучены, а код с примерами выкачен позже — ничего делать не обязательно: ночная сверка подберёт примеры сама (до 2 000 заданий за ночь вместе со словами, то есть 5 тыс. примеров — за три ночи). Сразу и все — `php artisan audio:pregenerate --all --only=examples`; затем `audio:coverage <slug> --verify` (строка `Examples: …`).

Хотите сначала обкатать Google без R2 — пропустите шаги 3–5: файлы будут ложиться на сервер. Перейти на R2 позже — шаги 3–5 в любой момент (`audio:migrate-disk` перенесёт уже созданное).

### C5. Проверка файла в R2

```bash
curl -sI https://audio.ваш-домен/audio/<имя-файла>.mp3 | grep -i -E "HTTP|cf-cache-status|cache-control|content-type"
```

Имя файла — колонка `Path` в выводе `audio:coverage --verify` или поле `audio_path` слова (у примера — `example_audio_path`). Ожидается `200`, `content-type: audio/mpeg`, `cache-control` с `max-age=31536000`, при втором запросе — `cf-cache-status: HIT`.

### C6. Справочник команд

| Команда | Что делает | Что печатает |
|---|---|---|
| `audio:sample [--voice=] [--voices=a,b,c] [--dir=] [--clear-halt]` | Сразу (без очереди) озвучивает контрольный набор ≈ 30 слов и фраз (короткие слова, омографы, сокращения, числа, даты, фразы, два диктанта) текущим драйвером в `storage/app/audio-samples/<голос>/` (`--dir` — другая папка; `--voices` — до 10 голосов за запуск, каждый в свою папку, docs/37 шаг 5). Символы считаются в месячный предел. `--clear-halt` сначала снимает маркер остановки (C8) | `Voice …, driver …, into …`; предупреждения о неизвестном `TTS_DRIVER`, не-гугловском голосе, маркере остановки; таблицу «текст → файл → размер» (вместо файла — код ошибки); итог `Voiced N of M` (код выхода 1, если что-то не вышло; после окончательной ошибки останавливается: `Stopped after a final error: …`) |
| `audio:pregenerate <slug>` / `audio:pregenerate --all` `[--only=words\|examples]` `[--force]` | Ставит в очередь `tts` задания для активных слов курса (или всех курсов, кроме своих колод учеников) и их основных примеров, у которых нет актуального файла (файл проверяется на диске). По умолчанию — слова и примеры; `--only=words` — только слова, `--only=examples` — только примеры. Нужен ровно один из `<slug>` и `--all`. `--force` — пересоздать и готовые (один вызов Google на уникальный текст за весь прогон — и между словами и примерами) | `--all`: по строке на курс `<slug>: queued N, already up to date M` (слова) и `<slug> examples: queued N, already up to date M` (примеры); итог `Queued: N, already up to date: M` (слова) и `Examples queued: N, already up to date: M` (примеры); с `--only` — только строки своего вида |
| `audio:reconcile [--limit=]` | Ночная сверка (её же запускает расписание): сначала слова курсов, у которых путь не совпадает с текущим текстом, затем основные примеры, у которых путь не совпадает с текущим примером; `--limit` (по умолчанию 2000) — **общий** на слова и примеры за раз. Диск не опрашивается | `Queued: N` и строку `Words: W, examples: E` или причину, почему ничего не поставлено (C8) |
| `audio:coverage <slug> [--verify] [--min=] [--limit=20]` | Отчёт по курсу: активные слова и слова с озвучкой, по модулям и всего. `--verify` проверяет сами файлы (на R2 — по HEAD-запросу на файл) и перечисляет битые (`missing` / `empty` / `stale`). `--min=95` — код выхода 1 ниже 95 % | таблицу по модулям; с `--verify` — `No broken audio files.` или список и подсказку `audio:pregenerate <slug>`; итог `<slug>: N of M active words voiced (X%)`; затем строка `Examples: N of M voiced (X%), by the DB.` (с `--verify` — `…, files checked.`): M — активные слова с примером, который озвучивается (не пустой и не длиннее 5 000 байт). Примеры в `--min` **не** входят — порог только по словам |
| `audio:migrate-disk [--from=public] [--to=] [--dry-run]` | Копирует файлы слов и примеров (общий файл — один раз) с одного диска на другой (по умолчанию на `TTS_AUDIO_DISK`). Повторять безопасно: уже скопированное пропускается. База не меняется | `public -> audio: N files; copied N, already there N, missing on public N, failed N.`; при `failed` — список и код выхода 1 |
| `audio:prune [--days=30] [--delete] [--disk=] [--force]` | Ищет старые файлы слов и примеров, на которые не ссылается ни одно слово (ни путь слова, ни путь примера, ни ожидаемые пути текущего слова и примера; включая выключенные слова) и которые старше `--days`, плюс остатки `.tmp/` старше суток. **Без `--delete` ничего не удаляет.** Файлы диктантов не трогает никогда. Если ни у одного слова нет ни озвучки слова, ни озвучки примера, а файлы есть — отказывается (похоже на чужую базу), `--force` это обходит | `would delete: …` / `deleted: …`; итог `<диск>: N files; in use N, younger than D days N, would delete N, failed N.` |

### C7. Что происходит само

| Событие | Что делает приложение |
|---|---|
| Новое слово в `/admin` | задание озвучки слова и (если есть пример) примера после сохранения |
| Импорт урока | задания по новым и изменённым словам и по примерам новых слов и слов, у которых файл примера не от текущего текста примера, после фиксации импорта (откат — ничего не ставится) |
| Правка английского текста слова | старый путь сбрасывается, ставится новое задание; пока файла нет — голос телефона |
| Правка основного примера слова в `/admin` (форма слова или список слов урока) | старый путь примера сбрасывается, ставится новое задание; пока файла нет — кнопки озвучки примера нет. Правка только пробелов файл сохраняет. Дополнительные примеры (вкладка примеров) не озвучиваются и заданий не ставят |
| Слово выключено | задание не ставится, файл остаётся (слово можно включить обратно) |
| Новая версия диктанта (редактор, импорт) | озвучка этой версии; статус и ошибка видны в списке заданий практики, «Сгенерировать аудио заново» — повтор |
| Каждую ночь в 02:30 UTC | `audio:reconcile`: слова, затем примеры без актуального файла получают задание (до 2000 за ночь на всё вместе) — страховка от потерянных заданий и добор после предела месяца |
| Свои колоды учеников | **не озвучиваются Google** ни одним из путей выше: голос телефона |

Пока `TTS_DRIVER=null` (или опечатка), новые слова, импорт, правки и ночная сверка заданий не ставят (правка текста или примера сбрасывает путь — сверка озвучит после включения). Одно и то же слово, пока его задание ждёт в очереди, второй раз не ставится (задание слова и задание его примера — разные и ждут рядом). Один и тот же текст в разных словах и курсах — один файл и один вызов Google.

### C8. «Требуют внимания» и неполадки

Строки озвучки на главной `/admin` в блоке «Требуют внимания»:

| Строка | Когда | Что делать |
|---|---|---|
| `<slug> · озвучка` — «Покрытие X %, порог публикации 95 %» | у опубликованного курса или курса на проверке озвучено меньше 95 % активных слов (по базе, файлы не проверяются) | `audio:pregenerate <slug>`, после очереди — `audio:coverage <slug> --verify` |
| «Google TTS · расход за месяц» — «Израсходовано X % …» | только при `TTS_DRIVER=google`, от 90 % месячного предела | посмотреть, что съело объём; при необходимости поднять `TTS_MONTHLY_CHAR_LIMIT` (не выше бесплатного миллиона, если не хотите платить) |
| то же — «Предел исчерпан …» (красная) | предел месяца достигнут | ничего: слова доозвучит ночная сверка в новом месяце (по тихоокеанскому времени); диктанты получили ошибку `tts_monthly_limit_reached` — в новом месяце «Сгенерировать аудио заново» |
| «Google TTS · вход отклонён» (красная) | Google отклонил ключ (`tts_auth_failed` или `tts_forbidden`), озвучка остановлена | см. ниже «маркер остановки» |
| «Очередь озвучки» | в очереди `tts` больше `TTS_QUEUE_ATTENTION_SIZE` заданий | при массовом прогоне — нормально; иначе проверить, что воркер `queue-low` работает и у него `--queue=low,tts` |

Коды ошибок (видны в `failed_jobs` — `php artisan queue:failed`, в логе `audio.pregenerate_failed`, у диктантов — в колонке ошибки озвучки):

| Код | Что значит | Что делать |
|---|---|---|
| `tts_service_not_configured` | драйвер `null`, у `http` нет `TTS_SERVICE_URL`, у `google` пуст `GOOGLE_TTS_CREDENTIALS`, или `TTS_DRIVER` с опечаткой | задать переменные (C2) |
| `tts_credentials_invalid` | файл ключа не найден, не читается (права, C1), не JSON или не ключ сервисного аккаунта; `GOOGLE_TTS_KEY_FILE` не задан (подключён `/dev/null`) | проверить путь на хосте, права `0440` на GID 1000, что это тот JSON из A3; пересоздать контейнеры |
| `tts_voice_unsupported` | `TTS_VOICE` — не голос Google (часто: остался `en-US-AriaNeural`) | задать голос из A5 |
| `tts_auth_failed` | Google дважды отклонил подпись (401): ключ удалён в консоли, или часы сервера сильно расходятся | новый ключ (C10) или синхронизация времени; затем снять маркер |
| `tts_forbidden` | 403: API не включён (A2), нет оплаты (A1), ключ из другого проекта, нет роли (A3) | исправить в консоли Google; затем снять маркер |
| `tts_monthly_limit_reached` | достигнут `TTS_MONTHLY_CHAR_LIMIT` | слова ждут нового месяца сами; диктанты — повтор в новом месяце |
| `tts_rate_limited` | Google ответил 429/408 или свой ограничитель темпа не дождался очереди за 30 с | ничего: задание повторится само (5 попыток с паузами 30 с, 2, 10, 30 мин) |
| `tts_service_failed` | Google недоступен или ответил 5xx / оборвалась связь | повторится само; если массово — проверить исходящий доступ сервера к `texttospeech.googleapis.com` |
| `tts_request_rejected` | Google отклонил сам запрос (400) — редкий случай, например текст длиннее 5 000 байт | посмотреть текст слова/диктанта (пример длиннее 5 000 байт в очередь не ставится вовсе) |
| `tts_audio_not_stored` | Google ответил, а диск не принял файл: неверные `AUDIO_*`, у токена R2 нет записи или он на другой бакет; для `public` — права на папку | исправить и перезапустить: `php artisan queue:retry all`. Задание слова делает только 2 попытки, а не 5 — каждая стоит символов |

**Маркер остановки.** После `tts_auth_failed` или `tts_forbidden` приложение на 10 минут перестаёт обращаться к Google: все задания сразу завершаются тем же кодом (иначе тысячи заданий подряд получили бы тот же отказ). Ночная сверка в это время ничего не ставит. Исправив ключ или проект, снимите маркер и проверьте вход одной командой:

```bash
php artisan audio:sample --clear-halt
```

Затем верните упавшие задания: `php artisan queue:retry all` (или `audio:pregenerate --all` — поставит только то, что не озвучено).

**Почему ночная сверка ничего не поставила.** `audio:reconcile` пишет причину одной строкой:

| Строка | Причина |
|---|---|
| `TTS is not configured (TTS_DRIVER=null): nothing queued.` | озвучка выключена |
| `TTS_DRIVER is none of deepgram, google, http or null: nothing queued.` | опечатка в `TTS_DRIVER` |
| `Google refused the sign-in … nothing queued.` | висит маркер остановки |
| `TTS_DRIVER=google, but GOOGLE_TTS_CREDENTIALS is empty: nothing queued.` | не задан путь к ключу |
| `… the key file of GOOGLE_TTS_CREDENTIALS is missing, unreadable or not a service-account key …` | ключ не читается (C1) |
| `TTS_VOICE is not a voice of Google …` | голос не Google (A5) |
| `The monthly TTS character limit is spent: nothing queued until next month.` | предел месяца |

Ручной запуск: `php artisan audio:reconcile`.

**Прочие признаки.**

| Признак | Что проверить |
|---|---|
| Файл есть в бакете, но в Mini App тишина | nginx пересоздан после `AUDIO_PUBLIC_URL` (CSP `media-src`)? `AUDIO_PUBLIC_URL` совпадает с доменом бакета? CORS и Transform Rules **не нужны** |
| nginx не стартует после задания `AUDIO_PUBLIC_URL` | адрес не `https://…` или с пробелом/переводом строки |
| `cf-cache-status: DYNAMIC` | правило кэша B3 не применилось к этому хосту |
| Очередь стоит | работает ли `queue-low`, есть ли у него `tts` в `--queue`; `php artisan queue:failed` |
| `/health/ready` показывает `"tts": "degraded"` | опечатка в `TTS_DRIVER` |
| У части учеников файл не грузится | доступность домена Cloudflare у оператора; временно `TTS_AUDIO_DISK=public` — файлы с сервера (их туда нужно сначала вернуть: `audio:migrate-disk --from=audio --to=public`, или переозвучить) |

### C9. Смена голоса

1. Выбрать новый голос через `audio:sample --voice=…`.
2. Поменять `TTS_VOICE` (или поднять `TTS_AUDIO_VERSION`, если голос тот же, а файлы нужно пересоздать), пересоздать контейнеры.
3. `php artisan audio:pregenerate --all` — **без `--force`**: у нового голоса другие имена файлов, они и так считаются «не озвученными». Это полный повторный прогон: символы всех слов, примеров и диктантов заново (в пределах месячного лимита; не хватит — ночная сверка доберёт в следующем месяце).
4. Пока прогон идёт, слова, которые ещё не переозвучены, звучат голосом телефона (старый файл к новому голосу не подходит).
5. Когда `audio:coverage --verify` по всем курсам в порядке — убрать старые файлы: `php artisan audio:prune` (посмотреть список), затем `php artisan audio:prune --delete`. Файлы моложе `--days` (30) остаются; чтобы убрать сразу — `--days=1`.

Диктанты переозвучиваются по новой версии задания или кнопкой «Сгенерировать аудио заново»; `audio:prune` их не трогает.

### C10. Смена ключей

- **Google:** в консоли создать новый ключ (A3) → положить новый файл на хост по тому же пути `GOOGLE_TTS_KEY_FILE` (права как в C1) → пересоздать контейнеры `app`, `queue-low`, `scheduler` → `php artisan audio:sample --clear-halt` (проверка входа) → удалить старый ключ в консоли.
- **R2:** создать новый токен (B4) → заменить `AUDIO_ACCESS_KEY_ID` / `AUDIO_SECRET_ACCESS_KEY` → пересоздать контейнеры (без Docker — `config:cache` и `queue:restart`) → отозвать старый токен.
