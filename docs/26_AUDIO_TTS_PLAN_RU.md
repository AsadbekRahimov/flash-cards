# Озвучка: Google Cloud TTS + Cloudflare R2 — план реализации

Статус: **план, код не написан** (решение владельца 20.11.2026). Настройка внешних сервисов — `docs/27_GOOGLE_TTS_SETUP_RU.md`.

## 1. Решение

| Что | Как |
|---|---|
| Синтез речи | Google Cloud Text-to-Speech, один раз на текст, в фоне (очередь `low`) |
| Хранение и отдача слов и примеров | Cloudflare R2, публичный бакет на своём поддомене, кэш Cloudflare |
| Диктанты практики | остаются на сервере, отдаются через защищённый адрес API (docs/16 §10.5) |
| Новое и изменённое содержимое | озвучивается автоматически заданиями очереди |
| Синтез «на лету» при запросе ученика | выключается (см. §5.5) |

## 2. Что уже есть и остаётся

- Имя файла слова строится от содержимого: `audio/{sha1(текст|голос|версия)}.mp3` (`WordAudioService::pathFor`). Один текст в разных курсах — один файл. Изменился текст, голос или `TTS_AUDIO_VERSION` — получается новое имя, старый файл просто перестаёт использоваться.
- Диск слов задаётся настройкой `twa.tts.audio_disk` — код уже не привязан к локальной папке.
- Правка английского текста слова в админке: `LessonContentRefresher::wordEdited` → `WordAudioService::textChanged` сбрасывает `audio_path` и ставит `PregenerateWordAudioJob`.
- Диктанты: у каждой версии задания свой `audio_status`; `PracticeAudioService::schedule` ставит `GeneratePracticeAudioJob` при новой версии, в админке есть «озвучить заново».
- `audio:pregenerate <курс> [--force]`, `audio:coverage <курс> [--verify] [--min=]`, блок «Требуют внимания» в `/admin` (покрытие ниже 95 %).
- Зависимость `league/flysystem-aws-s3-v3` уже установлена (резервные копии в R2) — новых пакетов для R2 не нужно.

## 3. Чего нет (это и делаем)

1. Клиента Google Cloud TTS: сейчас `TtsFallbackService` умеет только `POST {TTS_SERVICE_URL}/tts` (формат edge-tts).
2. Диска R2 для озвучки и адреса файлов на другом домене (CSP `media-src 'self'` его не пропустит).
3. Автоматической озвучки **новых** слов: при создании слова в админке и при импорте урока задание не ставится — только ручной `audio:pregenerate`.
4. Озвучки **примеров**: Mini App озвучивает только само слово; у примера нет ни файла, ни кнопки.
5. Уборки файлов, на которые больше ничего не ссылается.
6. Ограничителя расхода: ошибка или цикл в коде не должны выйти за бесплатный объём Google.

## 5. Устройство

### 5.1 Синтезатор за интерфейсом

`App\Domain\Content\Contracts\SpeechSynthesizer::synthesize(string $text, string $voice): array{body, content_type}` и три реализации, выбор — `TTS_DRIVER`:

- `google` — Google Cloud TTS (`text:synthesize`, MP3);
- `http` — нынешний edge-tts-совместимый сервис (`TTS_SERVICE_URL`), оставляем для локальной разработки;
- `null` — ничего не настроено: задания завершаются понятной ошибкой `tts_not_configured`, как сейчас.

`WordAudioService` и `PracticeAudioService` получают интерфейс вместо `TtsFallbackService`. Тесты подменяют интерфейс; настоящих вызовов Google в тестах нет.

### 5.2 Клиент Google (**к architect**: безопасность)

- Вход — сервисный аккаунт. Ключ JSON лежит файлом на сервере вне репозитория (`GOOGLE_TTS_CREDENTIALS=/run/secrets/google-tts.json` или содержимым в переменной), в образ и в git не попадает.
- Токен доступа: подписанный JWT (RS256, `openssl_sign`) → обмен на токен на `oauth2.googleapis.com/token`, область `cloud-platform`; токен кэшируется в Redis на срок жизни минус запас (ключ с версией, массив, TTL — правила docs/19 §3). Это без нового пакета. Альтернатива — пакет `google/auth` (новая зависимость, нужно согласие владельца). Решение — за architect.
- Запрос: `POST https://texttospeech.googleapis.com/v1/text:synthesize`, `audioConfig.audioEncoding = MP3`, частота и битрейт — одни для всех файлов; ответ — base64 в `audioContent`.
- Ошибки: 429 и 5xx — повтор задания с паузой (как сейчас у `PregenerateWordAudioJob`); 400/403 — без повторов, запись причины; ключ и токен в логи не попадают.
- Лимиты Google: до 5 000 байт на запрос (наши тексты короче), по умолчанию 200 запросов в минуту для Chirp 3 и 1 000 для Neural2 — задания идут с ограничением темпа (`RateLimited` middleware очереди), чтобы первый прогон на 11,5 тыс. файлов не упёрся в квоту.

### 5.3 Голос

Одна настройка `TTS_VOICE` (например `en-US-Chirp3-HD-…` или `en-US-Neural2-…`) и `TTS_AUDIO_VERSION`. Перед массовым прогоном владелец слушает контрольный набор (команда `audio:sample`, 30 слов и фраз: короткие слова, омографы, сокращения, числа) и утверждает голос. Одиночные короткие слова — главный риск качества; если у выбранного голоса начало слова обрезается или интонация вопросительная — берём Neural2.

### 5.4 Хранение и отдача

- Новый диск `audio` (`driver: s3`, свой бакет и ключи `AUDIO_*`, не ключи резервных копий), `url` = `AUDIO_PUBLIC_URL` (например `https://audio.example.uz`). `twa.tts.audio_disk` берётся из `TTS_AUDIO_DISK` (по умолчанию `public` — локально и в тестах ничего не меняется).
- Запись в R2 одним `put` (в S3 запись объекта атомарна — приём «временный файл + переименование» нужен только локальному диску); `Cache-Control: public, max-age=31536000, immutable` на объекте: имя файла от содержимого, менять его нечем.
- `isReady()` для R2 не ходит в бакет на каждый запрос ученика: готовность — это заполненный `words.audio_path`, равный ожидаемому пути (так `urlFor` работает уже сейчас). Проверка наличия файла — только в заданиях и в `audio:coverage --verify`.
- CSP: в `media-src` всех nginx-конфигов добавить домен озвучки из переменной; тест `check-api-surface`/конфигов обновить.
- Диктанты: диск `practice_audio` остаётся локальным (файлы закрыты, отдаются через JWT). На нескольких серверах или при переезде они пересоздаются командой; в R2 не выносим.

### 5.5 Синтез «на лету» (`GET /api/twa/tts`)

С платным синтезатором открытый адрес «озвучь любое слово» — способ потратить чужие деньги. Решение: адрес отдаёт **только готовый файл** (редирект на адрес R2 или 404), синтез по запросу ученика убираем. Если файла нет, Mini App, как и сейчас, использует голос телефона. (**к architect**: подтвердить и проверить, что свои колоды учеников не остаются без звука — у них текст произвольный; вариант — озвучивать слова своих колод заданием очереди с дневным лимитом на ученика.)

### 5.6 Когда ставится задание

| Событие | Сейчас | Будет |
|---|---|---|
| Правка текста слова в админке | задание ставится | без изменений |
| Новое слово в админке | нет | задание после сохранения |
| Импорт урока (новые и изменённые слова) | нет | задания по всем затронутым словам после фиксации транзакции |
| Слово выключено | — | задание не ставится, файл остаётся |
| Новая версия диктанта | задание ставится | без изменений |
| Правка примера | — | задание на пример (§5.7) |
| Смена голоса / версии | вручную `audio:pregenerate` | то же + команда на все курсы сразу (`audio:pregenerate --all`) |
| Ночная сверка | нет | команда по расписанию: слова и примеры без актуального файла → задания (страховка от потерянных заданий) |

Все задания идемпотентны: есть файл с нужным именем — синтеза нет, строка только догоняет путь.

### 5.7 Примеры

- Поле `words.example_audio_path` (миграция с `down()`), путь строится тем же `pathFor(текст примера)` — одинаковые примеры делят файл.
- Задание `PregenerateExampleAudioJob`, вызов из тех же точек, что и для слова, при изменении `example`.
- API: `example_audio_url` в ресурсах занятия (только когда путь актуален); Mini App — кнопка озвучки у примера в панели ответа. Нет файла — кнопка не показывается (голос телефона для длинной фразы звучит заметно хуже, чем для слова).
- `audio:coverage` и «Требуют внимания» считают примеры отдельной строкой; порог публикации курса (95 %) остаётся по словам.

Этап отдельный: слова и диктанты запускаются без него.

### 5.8 Уборка

`audio:prune [--dry-run] [--days=30]`: файлы в бакете, на которые не ссылается ни одно слово и ни один пример, старше N дней — удалить. Запуск вручную или раз в месяц; по умолчанию `--dry-run`. При объёмах проекта это вопрос порядка, а не денег.

### 5.9 Ограничитель расхода

- Счётчик символов, отправленных в Google, за текущий месяц (Redis + строка в БД раз в день) и предел `TTS_MONTHLY_CHAR_LIMIT` (по умолчанию 900 000 — ниже бесплатного миллиона). Достигнут — задания откладываются до следующего месяца, в «Требуют внимания» появляется строка.
- В Google Cloud — бюджет с оповещением (docs/27 §5): вторая линия защиты.

## 7. Порядок включения на сервере

1. Настроить Google Cloud и R2 по docs/27.
2. Выкатить код с `TTS_DRIVER=null` — ничего не меняется.
3. Задать переменные, `audio:sample` → послушать → утвердить голос.
4. `audio:pregenerate --all`; следить за очередью `low` и `audio:coverage`.
5. Проверить в Mini App на телефоне: слово звучит с домена озвучки, в Remote Debugging нет ошибок CSP.
6. `LEARNING_LADDER_AUDIO_REQUIRES_FILE=true` уже стоит: упражнения на слух начнут выдаваться сами по мере появления файлов.

## 8. Риски

- **Карта и регистрация в Google Cloud из Узбекистана** — не проверено; без платёжного профиля API не включается.
- **Качество одиночных слов** у «живых» голосов — проверяется набором `audio:sample` до массового прогона.
- **Доступность домена Cloudflare** у операторов учеников — проверить на 2–3 операторах; запасной путь — `TTS_AUDIO_DISK=public` (файлы с сервера), переключение без правок кода.
- **Утечка ключа сервисного аккаунта** — у аккаунта нет прав, кроме вызова TTS; ключ вне репозитория; ограничитель расхода и бюджет ограничивают ущерб.
- **Смена голоса** — это полный повторный прогон (новые имена файлов); старые файлы убирает `audio:prune`.
