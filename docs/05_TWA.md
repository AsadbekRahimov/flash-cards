# 05. Telegram Web App (TWA) — Спецификация

## 1. Стек и структура

- **Framework:** Vue 3 (Composition API) + `<script setup>`.
- **Build:** Vite 7.
- **State:** Pinia.
- **Routing:** Vue Router (history mode внутри TWA).
- **HTTP:** ofetch или axios.
- **UI:** TailwindCSS 4 (`@tailwindcss/vite`, конфиг в `src/style.css`: `@theme`, токены `--tg-*`) + локальные компоненты (без тяжёлой UI-либы, чтобы размер bundle был маленьким).
- **Telegram SDK:** `@twa-dev/sdk`.
- **Icons:** Heroicons 2.2 (MIT), **вендорные** — пути SVG лежат в `src/components/ui/icons.ts` (**53 иконки**, outline + solid; лицензия в шапке файла; практика добавила три: `arrows-right-left` «Найди пары», `puzzle-piece` «Подбери сочетание» и вход «Практика», `bars-3-bottom-left` «Собери предложение» — «Слушай и пиши» рисуется прежним `speaker-wave`), рисует их `AppIcon`; npm-пакета иконок нет. Файл собирается в отдельный чанк `icons` (`vite.config.ts`), чтобы он кешировался между релизами.
- **Дизайн-система:** токены, CSS-компоненты (`.page`, `.card`, `.btn-*`, `.field`, `.list`, …) и UI-компоненты `components/ui/*` — `docs/14_UX_AUDIT_AND_REDESIGN.md` §4; API компонентов описан в JSDoc каждого файла.

Размер цели: первый бандл ≤ 180 KB gzip.

**Совместимость WebView (Tailwind 4):** CSS использует cascade layers, `@property`, `color-mix()`; официально поддерживаются Safari 16.4+, Chrome 111+, Firefox 128+. В проекте нет `browserslist` (JS-таргет `es2020`), CSS-фолбэков для старых WebView нет: на Android с System WebView < 111 (старые устройства без обновления WebView) стили могут отображаться некорректно/пропасть. Риск принят владельцем; при росте жалоб — вернуться на Tailwind 3.4 или добавить проверку версии WebView.

**«Удалить аккаунт»** (решение владельца 03.11.2026). Последняя группа экрана «Настройки» — «Опасная зона» с одной строкой «Удалить аккаунт» (≥ 52 px). Нажатие ничего не удаляет: открывается лист `DeleteAccountSheet` (`BottomSheet`) — что произойдёт: данные удаляются окончательно через 30 дней; вернуться можно до этого срока командой `/start` в боте; платёжные записи хранятся по закону; подписка Pro прекращается. «Да, удалить» (`btn-danger`) → `POST /me/delete {confirm: true}` (docs/04 A.2c) → `authStore.logout()` и переход `replace` на `/account-deleted`; отказ остаётся в листе (`InlineAlert`), сессия не сбрасывается. После удаления экран не делает запросов: запрос со старым токеном получил бы 401, обновил токен через `/auth` и этим **восстановил** бы аккаунт. **«С возвращением! Аккаунт восстановлен»** (R11b). Если ответ `POST /auth` несёт `account_restored` (docs/04 A.1), оболочка приложения (`App.vue`) один раз за сессию открывает лист `AccountRestoredSheet` (`BottomSheet`) поверх любого экрана, с которого открыто Mini App, включая deep link: «Аккаунт восстановлен — слова и прогресс на месте.», при `pro_can_resume` — ещё «Автопродление Pro было выключено при удалении…» и кнопка «Открыть «Подписку»» (→ `/billing`); «Понятно» закрывает. Стор `auth` берёт поле из ответа `/auth`, лист забирает его (`takeAccountRestored`) и сразу один раз вызывает `POST /me/account-restored/seen` (docs/04 A.2d; ошибка игнорируется). Флаг «показано» живёт в сторе всю сессию: перелогин после истечения токена (~15 мин) лист не повторяет, даже если `seen` не дошёл. Лишних запросов `/me` нет. Тексты — `restored.*` (ru/uz).

Определяем режим по параметрам query из ссылки, которую бот прислал.

**Нижняя навигация.** `meta.tab` (`today` | `courses` | `rating` | `profile`, тип `TabId` в `router/index.ts`) указывает, к какой вкладке относится экран. `App.vue` показывает `TabBar` только для маршрутов с `meta.tab` и отодвигает под него содержимое; активная вкладка — по `route.meta.tab`, поэтому внутренние экраны (курс, настройки) оставляют свою вкладку подсвеченной. «Погружение» (`/training/*`, `/finished`, `/exam/*`, `/practice/sessions/*`, `/battles/:id`, лендинг) идёт без таб-бара; хаб практики (`/practice/:slug`) — экран вкладки «Курсы», настройка баттла (`/battles/new`) — вкладки «Рейтинг». Состав вкладок — docs/14 §5.1.

Прямая ссылка из чата (`startapp`, `router/startParam.ts`) может вести и на экраны практики: путь `/practice/<slug>?lesson=<id>`, `/practice/sessions/<id>`, `/battles/<id>` кодируется base64url (как остальные пути), а `resolveStartTarget` принимает любой путь, который резолвится в маршрут (проверка — `router/__tests__/practiceRoutes.spec.ts`).

**Прокрутка.** Прокручивается вся страница (`window`), собственных контейнеров прокрутки у оболочки нет. `scrollBehavior` роутера: новый экран открывается сверху, возврат (история, `router.back()`) — на сохранённую позицию, которую применяют, когда экран снова достаточно высок (он грузит данные при монтировании; ждут не дольше секунды). Правило — docs/14 §5.3.

## 4. Аутентификация

```ts
// src/composables/useTelegram.ts
import WebApp from '@twa-dev/sdk'

export function useTelegramInitData(): string {
  const data = WebApp.initData
  if (!data) throw new Error('TWA opened outside Telegram')
  return data
}
```

```ts
// src/stores/auth.ts
export const useAuth = defineStore('auth', {
  state: () => ({ token: '' as string, expiresAt: 0, learner: null as Learner | null }),
  actions: {
    async login(context: { type: 'training' | 'exam'; sessionId: number }) {
      const initData = useTelegramInitData()
      const res = await api.auth.authenticate(initData, context)
      this.token = res.token
      this.expiresAt = Date.now() + res.expires_in * 1000
      this.learner = res.learner
    },
    async ensure(context) {
      // One learner for every session: a context change needs no new token.
      if (!this.token || Date.now() > this.expiresAt - 60_000) {
        await this.login(context)
      } else {
        this.context = context
      }
    },
  },
})
```

> Схема, а не копия: в коде стор называется `useAuthStore` (`stores/auth.ts`), `initData` берётся из `useTelegram().initData()`, запрос идёт через `api.auth.authenticate`; перед запросом экран зовёт `auth.ensure()` (контекст сессии — по необходимости).

Перед каждым запросом вызываем `auth.ensure({ type, sessionId })`; если бек вернул 401 — пробуем один раз переавторизоваться (`api/client.ts`). Смена контекста новый токен не требует: learner один на все сессии, доступ к сессии проверяет сервер по членству (403 `not_a_member`). `context` остаётся только для аналитики.

### 5.2 Экран тренировки

> Макет и состояния — docs/14 §6.2; ниже — что делает код (`TrainingView` и компоненты упражнений).

Иммерсивный экран без таб-бара: шапка, карточка по центру и **действия внизу экрана** — липкий блок `StickyActions` (под большой палец, с отступом под home-индикатор).

- **Шапка:** ✕, полоса прогресса и счётчик «7 / 25»; под ней «Повторение» (ежедневное занятие, `daily_review`) или «Модуль 2 · Урок 4 · Еда и напитки» (урок). ✕ и системная «Назад» — одно действие: в личной сессии (`lesson`, `daily_review`) они ведут на «Главную» (`/today`), в групповой (`group_lesson`, открыта из чата группы) закрывают Mini App (docs/14 §5.3). Уход ничего не теряет: оценка уходит на сервер в тот момент, когда ученик её дал (нажал оценку флеш-карты, выбрал вариант, отправил набранный ответ), а не при показе следующей карточки.
- **Упражнение** выбирает `prompt.type` выданной карточки (docs/13 §2.5); карточка без `prompt` — флеш-карта.
  - **Флеш-карта** (`flash`). Чип типа по `card_kind`: `new` — «Новое слово», `learning` — «Закрепление» (карточка в минутных learning steps, вернётся в этой же сессии), `due` — «Повторение». Круглая кнопка озвучки — `useTts().speak(...)` (§7), слово (36 px, bold), транскрипция. Внизу одна кнопка «Показать перевод»; после неё — перевод с примером, вопрос «Насколько хорошо вы помните слово?» и три кнопки с подсказкой, что будет с карточкой: **«Не помню»** («повторим сегодня»), **«Помню»** («по расписанию»), **«Легко»** («покажем реже»).
    Оценка уходит в `POST /review` как `quality` **2 / 4 / 5** (Again / Good / Easy, docs/06 §2). Значения прежние, изменились подписи: старая «Трудно» на деле означала провал (q = 2) и сбрасывала прогресс по слову.
  - **«4 варианта»** — «Выберите английское слово» (`reverse`: перевод → слово) и «Что вы услышали?» (`audio`: слово на слух → перевод). Четыре варианта-кнопки под карточкой, оценивает клиент. **Оценка уходит в `POST /review` сразу при выборе** (верный — `quality` 4, неверный — 2), один раз на карточку: если ученик после выбора закроет экран (✕, системная «Назад»), ответ уже сохранён. Карточка из ответа `/review` придерживается (стор `training`: статус `held`, поле `deferred`; экран вердикта набранного ответа здесь не показывается), пока ученик не увидел правильный ответ. Верный выбор подсвечивается зелёным, следующая карточка появляется через 0,7 с после выбора (если ответ сервера пришёл позже — сразу по приходу). **Неверный** подсвечивается красным, правильный вариант и пример остаются на экране, а переход — по кнопке **«Дальше»** внизу: она лишь показывает придержанную карточку и ничего не отправляет; нажатая, пока ответ сервера ещё в пути, она ждёт (спиннер) и открывает карточку по его приходу. Ошибка при отправке — обычный экран ошибки с «Повторить».
  - **Написание** (`spelling`) и **пропуск в примере** (`gap_fill`), Pro: поле ввода внизу (крупный шрифт, «Букв: 9»), «Проверить» и «Не знаю» (пустой ответ = промах); ответ оценивает сервер (`POST /review` с `answer`). Затем **вердикт**: иконка в цветном круге, «Верно!» / «Почти!» / «Неверно», «Правильный ответ» крупно, свой ответ зачёркнутым, кнопка «Дальше».
- После оценки флеш-карты, после вердикта набранного ответа или после «Дальше» / паузы в «4 вариантах»: очищаем карточку и показываем следующую из ответа `/review`. Если следующая — `null`, сессия закончена: клиент запрашивает `finish` и заменяет маршрут на `/finished` — один раз, как только статус стора стал `finished`, как бы он до него дошёл (оценка, «Дальше», «Повторить», сессия без карточек с самого начала). Если ученик к этому моменту уже ушёл с экрана (✕, «Назад»), ответ сервера никуда его не переносит. Сервер не вернёт `null`, пока в уроке остаются learning-карточки (learn-ahead, docs/06 §4), поэтому клиенту ждать/опрашивать не нужно.

### 5.3 Итог занятия (`/finished`)

Иммерсивный экран без таб-бара (docs/14 §6.3).

- «Отлично!» в зелёном круге и причина окончания по `done_reason` («Все слова урока пройдены», «На сегодня повторять нечего», …).
- Личная сессия: плитки «Карточек» / «Верно» (процент) / «Новых слов» из `finish`-summary, карточка «Цель дня: 8 из 20» с полосой и серия (в том числе «под угрозой»). Групповая сессия summary не имеет — только «Вы повторили N слов».
- «Следующее повторение — через N дней» (или «Сегодня»).
- Кнопки внизу: **«На главную»** (`btn-primary`, → `/today`), «Узнать о Pro» (`btn-tinted`, только при `new_quota_exhausted`; пейвол в этом случае открывается сам), «Закрыть» (`btn-plain`, `WebApp.close()`). Поля промокода здесь больше нет: оно в «Подписке» и в пейволе.

### 5.4 Edge cases
- Ошибка загрузки (сеть, 5xx) → `ErrorState` с кнопкой «Повторить».
- Сессия закрыта (410 Gone) → экран «Тренировка завершена» с причиной; у личной сессии, открытой этим запуском приложения, есть «Начать заново» (тот же урок или ежедневное занятие); иначе кнопка — тот же выход, что ✕ и системная «Назад» (docs/14 §5.3): «На главную» у личной сессии (`lesson`, `daily_review`), «Закрыть» (закрывает Mini App) у групповой и у сессии, о которой этот запуск ничего не знает.
- `quality` не отправился → сохраняем в localStorage, пробуем отправить при восстановлении связи. (На MVP можно без оффлайн-очереди — просто показать ошибку.)

## 5a. Практика и баттл (docs/16 §11, docs/15)

Четыре режима самостоятельной практики — «Найди пары», «Подбери сочетание», «Собери предложение», «Слушай и пиши» — и «Баттл 1 на 1» с другом. Практика не меняет обучение (карточки, цель дня, серию, лиги); сервер проверяет **все** ответы,
клиент только показывает вердикт и разбор (контракт — docs/04 A.16, A.17). Все тексты — через i18n (`practice.*`, `battle.*`, ru и uz), состояния — `LoadingState` / `ErrorState` / `EmptyState`, «Назад» — `useBackButton`, иконки — `AppIcon`.

### 5a.1 Входы в практику
Правило владельца (docs/15 §4): на главной одно основное действие «Начать занятие», практика — **вторичное** действие рядом с обучением. Все входы видны только при `me.practice.available` (`billing.practiceAccess`; пока `/me` не пришёл — входов нет); у Free при
`PRACTICE_PLAN=pro` вход живёт, но по нажатию открывает `PaywallSheet reason="practice"` вместо хаба. Дневной лимит Free (две сессии практики и один баттл, §5a.6) входы не прячет: исчерпанный — тот же вход, нажатие открывает `PaywallSheet reason="practice_limit"`.
- **Экран курса (`CourseView`)** — `btn-tinted btn-block` «Практика» под главной кнопкой (с чипом Pro при `pro_required`) → `practice-hub` курса. В **строке урока** — тихая кнопка-иконка «Практика урока» (`btn-plain btn-sm`, `AppIcon puzzle-piece`, видимые
  36 px и невидимая область нажатия 44 × 44 px от `.btn-sm::after`), `aria-label` называет урок: «Практика: Модуль 2 · Урок 4». Она **замыкает строку прогресса** («20 из 20 слов ⧉»), а не стоит второй кнопкой рядом с «Учить»: рядом с «Учить» она отнимала у названия 40 px
  (колонка текста на 320 px падала со 138 до 98 px, на узбекском — со 112 до 72 px, и слова ломались посередине). «Учить» остаётся действием строки; кнопка отключена, пока открывается урок, и у урока без слов. → `practice-hub` с `?lesson=<id>`.
- **Итог занятия (`FinishedView`)** — `btn-tinted btn-block` «Практика урока» (после урока) / «Практика курса» (после ежедневного занятия) **под** «На главную» (одна `btn-primary` на экране остаётся; перед «Узнать о Pro», когда исчерпан лимит новых слов).
  Кнопка есть, только если `finish` прислал `practice_entry` (docs/04 A.3; `null` — нет кнопки). Ведёт в хаб с `?from=finished`: роут передаёт хабу проп `from`, и сессии, открытые из этого хаба, получают `source = after_training` (иначе `hub`).
- **Друзья (`FriendsView`)** — баттл (§5a.5).
- **Хаб** — «Играть с другом» → выбор друга (`FriendPickerSheet`) → настройка баттла.

### 5a.2 Хаб и сессия
**`PracticeHubView`** (`GET /practice/hub`): заголовок — название урока («Еда»; у безымянного урока «Модуль 2 · Урок 4») или курса, под ним «Практика · Модуль 2 · Урок 4» (у безымянного урока — «Практика · <название курса>», у хаба курса — «Практика»). Состояния: загрузка (`LoadingState cards`); ошибка (`ErrorState` + «Повторить»); `practice_unavailable` → `EmptyState` «Практика пока недоступна» с «К курсу»;
хаб. В хабе нет `btn-primary`: главное действие — нажатие карточки. Блоки сверху вниз: приглашения на баттл (если есть), карточка «Продолжить» (`active_session`: режим, «выполнено N из M», полоса), четыре `ModeCard`, карточка баттла.
`ModeCard` — вся карточка одна кнопка (около 90 px высотой), когда режим можно играть (`available`, `pro_required` → пейвол, «Продолжить» в этом же месте); когда нельзя (`not_enough`, `disabled`) — обычный блок с причиной словами («Изучено слов: 2 из 3…») и кнопкой «Учить урок» (в хабе урока) /
«К урокам» (в хабе курса); при `audio_pending` / `no_audio_words` кнопки нет (учить больше не поможет). Незавершённая сессия: нажатие на режим при 409 `practice_session_active` открывает лист «Незавершённая практика» (`ActiveSessionSheet`): «Продолжить» / «Начать новую» (`replace_active`) / «Отмена». Карточка «Продолжить» и лист называют место сессии (`practice.placeOf`, docs/16 §11.4): место самого хаба — коротко («Модуль 2 · Урок 4 · Еда»), другое — с курсом впереди («Английский A1 · Модуль 2 · Урок 4 · Еда») по `course_title` и `lesson`, которые сервер присылает с сессией.
Отказ открытия — тост; открывается одна сессия за раз (вторая карточка в это время не реагирует). У Free под «Выберите режим» — тихая строка «Сегодня бесплатно: осталось 1 из 2»; с нулём карточки остаются, нажатие открывает пейвол `practice_limit` (§5a.6).

**`PracticeSessionView`** (`GET /practice/sessions/{id}` и ответы): иммерсивная колонка без таб-бара. Шапка: ✕ (≥ 44 px), полоса прогресса, «3 / 5», под ней «Модуль 2 · Урок 4 · Еда» (или название курса) и чип «Повтор ошибок» у повтора. Тело по `status` стора:
`idle`/`starting` — загрузка; `ready`/`submitting` — компонент режима (`modeComponents.ts`: таблица «вид элемента → компонент»; все получают `element`, `mode: 'solo' | 'battle'`, `disabled` и шлют `answer(payload)`, предложение и диктант ещё `skip`); `verdict` — `AnswerReveal`;
`finished` — `PracticeSummary`; `closed` (410) — «Практика завершена» + «К практике»; `error` — `ErrorState` + «К практике». Живая область `aria-live="polite"` всегда в DOM (вердикт читается экранным диктором); вердикт сопровождает хаптик (`success` / `warning` для опечатки / `error`), у пар — только конец раунда.
- **Пары** (`PairsBoard`): две колонки, слово слева и перевод справа в любом порядке; верная пара зелёная с галочкой ~0,4 с и уходит с доски, неверная красная с крестиком ~0,6 с и хаптик `error`; правильное соответствие не раскрывается; во время запроса доска не берёт другие нажатия. После раунда — `AnswerReveal` «Раунд 2 из 3 пройден» и число ошибок.
- **Сочетание** (`CollocationChoice`): фраза с пропуском-плашкой и три варианта; нажатие на вариант — **и есть ответ** (без «Проверить»).
- **Предложение** (`SentenceBuilder`): смысл на языке ученика, строка ответа и банк фрагментов; нажатие переносит фрагмент в конец строки, нажатие в строке возвращает его на своё место (занятая ячейка банка остаётся пустой — ничего не сдвигается), «Начать заново», «Проверить» активна, когда в строке все фрагменты; «Не знаю». Недособранная строка хранится в памяти страницы
  (`composables/sentenceDraft.ts`) до отправки и возвращается при возврате к элементу. Первая буква строки рисуется заглавной — только отображение, на сервер уходят id.
- **Диктант** (`DictationInput`): кнопка-круг «Прослушать», поле (`autocapitalize/autocorrect/spellcheck/autocomplete` выключены), «Проверить», «Не знаю». Текста задания на устройстве нет; клип грузится в `blob:` с `Authorization` (`usePracticeAudio`) заранее — пока читается разбор предыдущего — и играет по нажатию (`<audio>` создаётся в обработчике нажатия: жест на iOS).
  Клип не загрузился или не играет → лист `AudioTrouble`: «Повторить загрузку» / «Заменить задание» (`POST …/replace`, без штрафа; кнопка скрыта, когда замены кончились) / «Сейчас без звука» (в хаб). Пока клип не слышен, поле и кнопки ответа ждут: гадать вслепую нельзя. Web Speech для диктанта не используется.
- **`AnswerReveal`**: цветной круг с символом и вердикт словами («Верно!», «Есть опечатка», «Нужно исправить», «Подсказка» — цвет никогда не один), затем разбор по виду элемента — диктант: фраза как надо писать + «Прослушать снова» + ваш ответ пословно (у каждого слова символ и подпись, неверные подчёркнуты) + перевод и пояснение; предложение: верное предложение, «Можно и так» (другие допустимые порядки), ваша сборка; сочетание: фраза целиком, три варианта с отметками верного и выбранного, перевод;
  «Дальше» внизу (`StickyActions`), на последнем элементе ведёт к итогам.
- **`PracticeSummary`**: «Готово!» с причиной окончания («Практика пройдена» / «Время практики вышло…» / «Эта практика закрыта…»), три плитки «Выполнено N / M · Верно с первой попытки · Подсказки» (у пар — «Раундов · Верно с первой попытки · Ошибок»), строка «Время: 1:33 · Опечаток: 1», список ошибок (`ListGroup`: что это было, ваш ответ зачёркнут, чип вида ошибки со значком) или похвала, внизу `btn-primary` «Повторить ошибки» (если сервер сказал `retry_available`
  и повтор не был отклонён) иначе «Ещё раз» (новая сессия того же режима в том же месте), «В курс», «Закрыть».
Сессия, открытая ✕ / «Назад», **ничего не теряет**: ответы уходят на сервер сразу; подтверждения нет; возврат — через хаб («Продолжить»).

### 5a.3 Сторы и composables
- **`stores/practice.ts`** — хаб и сольная сессия. Хаб: `hub`, `hubStatus` (`idle` / `loading` / `ready` / `unavailable` / `error`), `loadHub` (хаб другого курса не показывается, пока грузится; устаревший ответ отбрасывается по `hubSeq`; уже показанный хаб при сбое остаётся). Открытие: `opening` (режим карточки, которая ждёт), `openError`, `conflict` (409 `practice_session_active`),
  `paywall`, `limitHit` (пейвол дневного лимита: счётчик исчерпан или 403 `practice_limit_reached`, §5a.6), `retryUnavailable`, `preloaded` (ответ `open` берётся `load()` вместо повторного запроса). Сессия: `status` (`idle` → `starting` → `ready` ⇄ `submitting` → `verdict` → … → `finished`; `closed` (410), `error`), `outcome` (последний ответ для разбора), `pendingRequestId` (**тот же uuid** при повторе после сетевой ошибки — сервер засчитает один раз; у пар id хранится по ключу пары — `pendingPairs`, docs/16 §11.4),
  `generation` (любой ответ чужого поколения отбрасывается), `elementSeq` (ключ компонента режима: новый элемент — новый компонент без остатков выбора), `audio` (слот клипа). Действия: `loadHub`, `open`, `load`, `answer`, `skip`, `replace`, `retry`, `again`, `continueAfterVerdict`. Ошибки: `element_not_current` / `pair_already_matched` → перечитать
  сессию; `answer_already_accepted` → показать вердикт из `details`; 410 → `closed`; `practice_pro_required` в середине сессии → пейвол поверх, сессия остаётся.
- **`stores/battle.ts`**, **`stores/battleSetup.ts`** — баттл (§5a.5). `stores/billing.ts` держит блок `practice` из `/me` (`practiceAccess`: пока `/me` не пришёл — «ничего нельзя», входов нет и строки Pro о практике нет: `pro_promise = 'none'`) и счётчики лимитов Free (`limits`, §5a.6); экран друзей для выбора соперника читает `stores/friends.ts`.
- **Composables.** `usePracticeAudio` — слот клипа (`idle` / `loading` / `ready` / `failed`): `load(url)` (fetch с токеном → `blob:`), `play()`, `revoke()`; повторный `load` того же URL ничего не делает, `{ force: true }` грузит заново. `usePolling(tick, { intervalMs = 2000, enabled })` — опрос только пока экран на виду
  (`visibilitychange`: в фоне стоп, при возврате чтение сразу), тики не накладываются, сбой удваивает паузу до предела, успех возвращает 2 с. `useServerClock` — `offsetMs = serverNow − Date.now()` (медиана трёх последних), `remainingMs(deadline)`. `useBattleAudio` — пять клипов диктанта-баттла, загруженные в комнате до «Готов».
  `requestId.newRequestId()` — uuid v4 для `request_id`. `practiceLabels` — иконки и названия режимов, «Модуль 2 · Урок 4 · Еда», «≈ N мин». `sentenceDraft`, `collocationPhrase` (разрез фразы по `___`), `battleTime` (оставшееся время по часам сервера), `useNow` (часы устройства как ref, тик 250 мс — для обратных отсчётов), `useWakeAt` (будит экран ровно в момент, когда сервер должен сменить состояние матча, не дожидаясь очередного опроса).
- **API-клиент** (`api/index.ts`): `api.practice.{hub, open, get, answer, replace, audioBlob}`, `api.battles.{options, list, invite, get, poll, round, accept, decline, cancel, ready, surrender, answer, audioFailed, audioBlob}`; `ApiClientError.details`; все типы — `api/types.ts` (`PracticeHubResponse`, `PracticeSession`, `PracticeElement` по `kind`,
  `PracticeAnswerResponse`, `PracticeSummary`, `Battle*`, `MeResponse.practice`, `SessionSummary.practice_entry`). Коды ошибок практики и баттла — в `KNOWN_ERROR_CODES` и `error.code.*` (ru/uz).

### 5a.4 Доступность и дизайн
Нажатия ≥ 44 px (`.option`, фрагменты `btn` min-h 48, карточки пар min-h 56; маленькие кнопки — невидимой областью `.btn-sm::after`, docs/14 §3); состояния `selected` / верно / неверно — **цвет + значок + текст**; вердикт и таймер — `aria-live="polite"`; строка ответа — `role="list"`, кнопки «Убрать: tea»; таймер раунда — `role="timer"`.
Только токены темы (никаких `red-600`, `text-white` и палитры Tailwind — это проверяет `designSystem.spec.ts`), без `v-html`: тексты заданий выводятся через `{{ }}`. Ширина — от 320 px, обе темы Telegram.

### 5a.5 Баттл 1 на 1 (экраны)
> Контракт (JSON по статусам, коды ошибок, лимитеры) — docs/04 A.17, ЛС-приглашение — B.14, правила матча и часы — docs/16 §8, безопасность — docs/07. Здесь — экраны и то, какие поля ответа сервера их рисуют (таблица в конце раздела). Экран ничего не решает сам: статус, счёт, вердикты, часы и итог — серверные.

- **Вход** — `FriendsView` (только при `me.practice.available && me.practice.battle`): строка «Идёт баттл» (`active` из `GET /practice/battles`; одно нажатие обратно в матч), блок «Приглашения на баттл» (`incoming`) с «Принять» / «Отклонить» (принятие ведёт в `battle`; формат выключили после приглашения — «Этот формат сейчас выключен — принять приглашение нельзя.», то же в комнате и в реванше на итогах; «Повторить» после сбоя экрана перечитывает и друзей, и список баттлов), у каждого друга `btn-tinted btn-sm` «Баттл» (`aria-label` называет друга) → `battle-new?friendship=<id>`;
  хаб практики — «Играть с другом» (выбор друга в листе) и приглашения (их число — `hub.battle.incoming_count`). «Реванш» — на экране итогов матча. ЛС бота ведёт на `/twa/battles/<id>` (docs/04 B.14): экран читает матч и рисует то, что в нём сейчас — приглашение, комнату, игру или итог; приглашение, которое уже закрыто (отклонено, отозвано, истекло), показывается итогом с причиной.
- **`BattleSetupView`** (`/battles/new`): друг из адреса, курс (каталог без колод и без курсов без слов; основной курс выбран по умолчанию; курс, который сервер отверг как `course_not_found`, из списка убирается), урок («Модуль 2 · Урок 4 · Еда» или весь курс), формат — четыре `BattleFormatCard` по `GET /practice/battles/options` на каждый выбор курса или урока
  (`available` — карточка-радио; `not_enough` — «Мало материала» и причина словами по `reason` и числам `available` / `required`; `disabled` — «Выключено»; везде `round_seconds` — лимит раунда), единственная `btn-primary` «Пригласить» → `POST /practice/battles` → `battle`. Сервер считает материал по языкам **обоих** игроков, поэтому формат может быть недоступен паре, хотя в соло он есть;
  кнопка отключена, пока `friend_access = no_access` («у друга нет доступа к практике») или выбранный формат не `available`. Состояния `pro_required` у формата сервер не присылает: Free-ученику при `PRACTICE_PLAN=pro` на весь запрос отвечает 403 `practice_pro_required` — открывается `PaywallSheet`. У Free над «Пригласить» — строка «Баттлов сегодня: осталось 1 из 1»; с нулём кнопка остаётся главной и по нажатию открывает пейвол `practice_limit` без запроса (§5a.6).
  Отказ объясняется словами: свой незавершённый баттл — со ссылкой на него (409 `battle_busy`), друг больше не друг (404 `friendship_not_found`, 403 `not_friends`), баттлы выключены (409 `battle_disabled`), практика недоступна (403), материал кончился (422 `battle_material_unavailable` — форматы перечитываются), формат выключили (409 `practice_mode_disabled`), у друга пропал доступ (409 `battle_friend_no_access`).
- **`BattleView`** (`/battles/:id`) следует за `status` матча, который отдаёт сервер:
  - `invited` / `room` — `BattleRoom`: отправленное приглашение — «Ждём ответа» с оставшимся временем (`invite_expires_at − server_now`) и «Отменить»; полученное — правила и «Принять» / «Отклонить»; комната — оба игрока с отметками готовности (`ready`), правила, лимит раунда, оставшееся время комнаты (`room_expires_at`), «Готов» (после нажатия — «ждём соперника»);
    у диктанта «Готов» ждёт загрузки пяти записей из `audio_preload` (`useBattleAudio`: blob по `audio_url`, тот же, что сыграет в раунде);
  - `countdown` — «3 · 2 · 1» по часам сервера до `starts_at`. Раунд 1 в отсчёте уже назван (`round.no = 1`), но фазы у него нет (`round.phase = null`), и ответ сервер не примет (409 `round_not_open`) — поле ответа появляется со `playing`; `audio_preload` в отсчёте ещё приходит (экран мог перезагрузиться между «Готов» и стартом);
  - `playing` — шапка (раунд «2 / 5», `BattleScoreboard` «Вы 100 : 125» — счёт **разрешённых** раундов, `RoundTimer` по `round.deadline_at`), компонент режима в режиме `battle` (**один окончательный ответ**: у пар сначала набор сопоставлений и «Проверить»), после ответа «Ждём соперника…» (`OpponentStatus` по `opponent_answered`),
    в конце раунда `BattleReveal` по `GET …/round` (`reveal.correct`, карточка каждого игрока с вердиктом и очками, пояснение, «Следующий раунд через …» по `phase_ends_at`);
  - `finished` / `closed` — `BattleResult`: исход крупно по `result.outcome` («Победа» / «Поражение» / «Ничья» / «Матч не состоялся»; `both_absent` и `voided` после старта — «Матч прерван»), причина словами по `end_reason` (у аннулированного диктанта — всегда «Матч отменён: запись недоступна.»: другой причины `voided` сервер не отдаёт, а выключение практики посреди матча редко), раунды списком (`result.rounds` — только разрешённые), «Реванш» `btn-primary` («Пригласить снова» после матча, который не состоялся; после отказа — только «К друзьям»), «К друзьям», «В курс».
    Предложение реванша (`rematch`: `status = invited` и `by_me = false`) показывается и принимается здесь же («Принять» / «Отклонить»), своё — «Вы предложили реванш» и «Открыть реванш»; реванш, который уже идёт (комната открыта), — «Реванш уже идёт» и «Открыть реванш», кто бы его ни предложил. Пока матч закончен недавно, экран раз в 5 с (до 2 минут) читает опрос — `rematch.by_me` приходит в нём (`GET …/poll` вне `twa-api`, дешевле `GET /battles/{id}`);
  - полоски под шапкой: «Нет связи, пробуем…» (опрос не прошёл; при 429 / 5xx — нейтральное «Сервер не отвечает…») и «Соперник потерял связь» (`opponent_present = false`) с числом секунд `opponent_absent_since + presence_grace_seconds − server_now`: в игре — «Если не вернётся за N с, победа ваша.», в комнате и отсчёте — «…матч отменится.». Число тикает и после перезагрузки то же; к его концу экран сам читает опрос (`useWakeAt`), «за 0 с» не показывается;
  - выход — ✕ / «Назад» → `LeaveConfirm`: в отправленном приглашении — «Выйти из комнаты?» с текстом «Приглашение будет отозвано.», в комнате и отсчёте — «Выйти из комнаты?» (матч отменится, соперник узнает; оба случая — `cancel`), в игре — «Сдаться и выйти?» (`surrender` с `{confirm: true}`; `btn-danger` «Сдаться», `btn-secondary` «Остаться»); сдача — поражение, даже если вы вели. Полученное приглашение ✕ просто оставляет — принять его можно позже. Лист следит за статусом, пока открыт: матч закончился (`finished` / `closed`) — лист закрывается; лист комнаты закрывается и тогда, когда началась игра (в «Сдаться и выйти?» он не превращается — для сдачи ✕ нажимают ещё раз); приглашение стало комнатой — меняется только текст листа.
- **Опрос.** `stores/battle.ts` читает `GET /practice/battles/{id}/poll` раз в 2 с (`usePolling`) только пока матч жив и экран на виду; смена `status` → перечитать матч (`GET /battles/{id}`), смена `round.no` / `round.phase` → перечитать раунд (`GET …/round`). Сбой (сеть, 5xx, 429) удваивает паузу до 10 с; чтения баттла (опрос, матч, раунд, список, форматы) ограничены по времени 8 с, действия (в том числе `invite`, `answer`, `audio-failed`) — 10 с; таймаут считается сетевым сбоем.
  «Новее» — больший `version` (при равном — поздний `server_now`). Часы раунда — серверные (`server_now` → `offsetMs`, медиана последних трёх), таймер лишь показывает остаток: 0:00 не блокирует ввод, ответ после нуля уходит и принимается ещё `deadline_grace_ms` (1,5 с; число приходит от сервера). Экран просыпается ровно к моменту, когда сервер переведёт матч дальше
  (`starts_at`, `phase_ends_at`, дедлайн + грейс), не дожидаясь очередного опроса (`useWakeAt`).
  Ответ раунда: один `request_id` на ответ раунда — им же идут до 3 автоповторов при потере ответа (сеть, 5xx, 429, тайм-аут) и ручное «Повторить» после них. Определённый отказ после неопределённого сбоя (`round_closed`, `round_not_open`, `battle_closed`) читается как «ответ мог быть принят»: без ошибки, правду покажут опрос и разбор; поздний ответ закрытого раунда вердикта не показывает.
  Опрос — основной heartbeat присутствия (любой запрос участника к живому матчу тоже обновляет `last_seen_at`, не чаще раза в 5 с): кто ушёл дольше чем на 30 с, тот проиграл — матч идёт без него.
- **Особые случаи.** Диктант: окончательный 503 при загрузке клипа в комнате → `POST …/audio-failed` (`verified: true` — матч аннулирован, `closed / voided`, экран показывает итог; `verified: false` — файл на месте: загрузка повторяется сама один раз, при новом сбое — кнопка «Повторить»; тот же клип повторно не сообщается, а отчёт, который так и не дошёл до сервера, ручное «Повторить» разрешает снова). Встречное приглашение: `POST /battles` (в том числе «Реванш») ответил 409 `battle_busy` с id приглашения друга **мне** —
  экран открывает `GET /battles/{battle_id}` и показывает «Принять»; иначе — «У вас уже есть активный баттл…» и кнопка «Открыть текущий баттл» (в комнате, на настройке и на итогах после «Реванш»). `practice_pro_required` при принятии или чтении матча — `PaywallSheet`, как везде в практике (docs/16 §3.2).

| Что на экране | Поле ответа сервера (docs/04 A.17) |
|---|---|
| «Ждём ответа… осталось 4:12» | `invite_expires_at − server_now` |
| «Комната закроется через…» | `room_expires_at` |
| «3 · 2 · 1» | `starts_at`, `countdown_seconds` |
| Таймер раунда | `round.deadline_at`, `round_seconds` |
| «Ждём соперника…» | `round.my_answered`, `round.opponent_answered` |
| Счёт «Вы 100 : 125» | `scores` (меняется только при разрешении раунда) |
| Разбор раунда | `GET …/round?no=` → `reveal.correct` / `me` / `opponent` / `explanation` / `translation` |
| «Следующий раунд через…» | `round.phase_ends_at`, `reveal_seconds` |

### 5a.6 Лимиты Free и пейвол «лимит на сегодня» (docs/18 §3, G1)
Free получает небольшую часть практики и баттла: **две сессии практики и один баттл в день** (значения — env сервера, `docs/18` §3). Счётчики считает сервер по локальному дню ученика; клиент показывает остаток и вовремя открывает пейвол. Pro и ученик без лимита ничего не видят.
- **Контракт.** Остаток — `limits` в `GET /me` (`practice.limits`) и в `GET /practice/hub`: `null` целиком (Pro, лимитов нет вовсе или практика закрыта) или `{sessions, battles}`, у каждого вида `{limit, used, remaining, resets_at}` (`resets_at` — ISO-8601 UTC, конец «сегодня» ученика). **Вид может быть `null` отдельно:** пустой env означает, что лимита этого вида нет (`{sessions: null, battles: {...}}` или наоборот) — строка, пейвол и остановка нажатия есть только у вида с объектом. Ответы 201 на `POST /practice/sessions` и `POST /practice/battles` (реванш тоже) — форма GET плюс ключ `limits` со значением после создания; у `GET /practice/sessions/{id}` и у остальных ответов баттла ключа нет, `GET /practice/battles/options` лимитов не несёт (источник — `/me`). Отказ — 403 `practice_limit_reached`, `details {kind: 'sessions' | 'battles', limit, used, resets_at}`. Один повтор ошибок (`source = retry`) сессии, открытой сегодня, лимит не тратит; второй повтор той же сессии, повтор повтора и повтор вчерашней сессии считаются как сессия — решает сервер, TWA повтор не останавливает. Принять баттл можно всегда. `practice_pro_required` (`PRACTICE_PLAN=pro`) остаётся с причиной пейвола `practice`.
- **Один источник счётчиков — `stores/billing.ts`.** `limits` пишут `/me`, хаб, 201 и отказ (`setLimits`, `noteLimitHit`); экраны читают `sessionLimit` / `battleLimit` и спрашивают `limitReached(kind)`. Ответ без `limits` вовсе (старый сервер) ничего не меняет. Счётчик, у которого `resets_at` уже прошёл, ничего не говорит: приложение, простоявшее открытым всю ночь, не держит ученика за вчерашним нулём — запрос уходит, решает сервер (`composables/practiceLimits.ts`). Строка при этом исчезает сама, в тот момент, когда сутки счётчика кончились: геттеры `sessionLimit` / `battleLimit` читают реактивное «сейчас» стора (`billing.now`), и его двигает `watchDay()` — один `setTimeout` на ближайший `resets_at` среди живых счётчиков (после него — на следующий), заводится с каждым новым словом о счётчиках (`setLimits`, `noteLimitHit`, `forgetLimit`) и не заводится, пока счётчиков нет; срок дольше предела `setTimeout` (≈24,8 суток) ждётся шагами. Минутный тик `useNow` не подошёл: он живёт в компоненте, а не в сторе, и тикал бы всё время, а не один раз в нужный момент. Отказ сервера по виду, у которого счётчика не было (ученика приняли за Pro, вид приняли за безлимитный), делает его счётчик исчерпанным. Приглашение, не ставшее матчем (отклонено, истекло, отозвано), бэкенд не считает баттлом дня и возвращает место, а счётчик на экранах — «до того». Поэтому: (1) когда такое приглашение ученика закрывается, стор баттла делает `billing.forgetLimit('battles')` — счётчик баттлов становится `null` (ни строки, ни остановки) и кеш `/me` сбрасывается, так что следующее чтение `/me` приносит верное число; (2) «Пригласить снова» после баттла, который не состоялся, идёт к серверу и не останавливается счётчиком экрана (после сыгранного матча «Реванш» при нуле по-прежнему открывает пейвол без запроса за приглашением, но сначала читает состояние реванша — опрос `readRematch`, кнопка на это время ждёт: если друг уже предложил свой реванш, нажатие ведёт в его битву, а не в пейвол — принять можно всегда, а сервер ищет встречное приглашение раньше лимита; так же — в любой уже открытый реванш; не прочиталось — слово счётчика, пейвол); (3) ноль баттлов в «Друзьях» перед пейволом **подтверждается** (в настройке «Пригласить» счётчик не проверяет вовсе: запрос уходит на сервер, см. «Остатка нет»): `billing.confirmLimit('battles')` читает `/me` заново (`force`) и решает по свежему счётчику — место вернули, значит пейвола нет. Если `/me` уже в полёте (экран сам начал читать его при открытии, а ученик нажал раньше ответа), второй запрос не уходит: `load()` возвращает промис того же запроса (`meRequests` на уровне модуля, один на стор; так же поступает любой другой вызов `load()`, с `force` или без), и `confirmLimit` ждёт его ответа и решает по его счётчику, а не по старому нулю; проигравший запрос (нет сети) ничего не бросает, `loadedAt` остаётся пустым — пейвола нет. После платежа (`onPaid`) такой запрос не ждут: он старше платежа, `/me` спрашивают заново. Не удалось прочитать (нет сети) — пейвола нет тоже: продавать Pro по числу, которое нельзя проверить, нельзя, действие само идёт к серверу и скажет, что не так. Вид «только Pro» (`limit = 0`) вопроса не требует: место там не возвращается.
- **Строка остатка** — вторичный текст (13/18, `--tg-hint`): без кнопки, чипа и цвета, переносится по словам, на 320 px не обрезается. Хаб — под «Выберите режим»: «Сегодня бесплатно: осталось 1 из 2». Настройка баттла — над «Пригласить», «Друзья» — под списком друзей (если есть друзья и баттлы включены): «Баттлов сегодня: осталось 1 из 1». Настройка баттла и «Друзья» читают `/me` при открытии обычным `billing.load()` (не чаще раза в 30 с, best effort — без `/me` экран работает без строки); хаб берёт остаток из своего ответа.
- **Остатка нет (`remaining = 0`).** Входы остаются на местах и выглядят как раньше; нажатие открывает `PaywallSheet reason="practice_limit"` без запроса за самим пейволом: карточки режимов и «Играть с другом» в хабе, «Ещё раз» на итогах практики — сразу; «Реванш» на итогах сыгранного баттла — после одного чтения состояния реванша (встречное предложение друга ведёт в его приглашение, см. выше); «Баттл» у друга в «Друзьях» — после одного чтения `/me` (см. выше: нулю баттлов верят, когда его подтвердил сервер; кнопка на это время ждёт; ушёл с экрана, пока ждал, — ничего не открывается, и пейвол не остаётся ждать следующего захода); «Пригласить» в настройке `/me` не читает, а спрашивает сервер: приглашение уходит всегда (кнопка ждёт ответа — «Приглашаем…», второе нажатие не второе приглашение), встречное приглашение друга ведёт в него без пейвола (409 `battle_busy` с id приглашения друга: сервер ищет его до проверки лимита), иначе 403 `practice_limit_reached` открывает пейвол с числами из `details`, а 201 (место вернулось) ведёт в новый баттл. Не блокируются: «Продолжить» и карточка режима с незавершённой сессией (она уже посчитана), «Повторить ошибки», «Пригласить снова» после баттла, который не состоялся (спрашивает сервер), «Принять» / «Отклонить» приглашения и реванша (в «Друзьях», в комнате, на итогах), комната и «Готов», «Вернуться в баттл».
- **Вид «только Pro» (`limit = 0`).** Сервер поддерживает значение 0 как «Free этого вида не получает вовсе». Строки остатка у такого вида **нет**: «осталось 0 из 0» ничего не говорит (`shownLimit` в `composables/practiceLimits.ts`; геттеры `sessionLimit` / `battleLimit` отдают для него `null`). Стена при этом стоит — `limitReached` видит вид с `limit = 0` как исчерпанный с первого нажатия, а `confirmLimit` не переспрашивает `/me` (место там не возвращается). Пейвол говорит не «закончилось» и не «завтра» — ничего не потрачено и ничего не вернётся: для практики — слово о практике, и оно не обещает баттлов, которых Free не лишён: если баттлы тоже только в Pro (`practiceAccess.battle` и их лимит 0) — прежний лид `paywall.lead_practice` («Практика — игры на закрепление слов и баттлы с друзьями — доступна в Pro.»), иначе (баттлы у Free есть — лимит ≥ 1 или без лимита, — выключены `PRACTICE_BATTLE=false`, или о них пока ничего не известно) — `paywall.lead_practice_solo` («Практика — игры на закрепление слов — доступна в Pro.»); для баттлов — «Звать друзей на баттл можно в Pro. Принять приглашение друга можно всегда.» (`paywall.lead_practice_limit_battles_pro`; приглашение друга принимается без лимита). Дальше, как у всех причин, «Pro скоро откроется.» или перечень того, что даёт Pro; времени сброса и «или сразу с Pro» в этих лидах нет.
- **403 `practice_limit_reached`** во всех местах создания — `practice.open` (хаб, «Ещё раз»), `battleSetup.invite` (при нуле это единственный путь к пейволу), `battle.rematch` — открывает тот же пейвол с числами из `details` и помечает счётчик исчерпанным; сессия и экран остаются, как при `practice_pro_required`. Если `details` не читаются, пейвол без цифр не показывается: говорит `error.code.practice_limit_reached` обычным путём ошибки (тост в хабе и на итогах, строка у кнопки в настройке).
- **Пейвол `practice_limit`** (`PaywallSheet`, проп `limitHit {kind, limit, used, resets_at}`). Лид зависит от вида и от режима листа:
  - практика, пока Pro только «скоро» (`coming_soon`): «Бесплатная практика на сегодня закончилась (2 из 2). Новая — завтра в 00:00.» и дальше, как у всех причин, «Pro скоро откроется.» — обещания «сразу с Pro» нет, купить нечего;
  - практика, пока Pro можно купить (`purchase`): «Бесплатная практика на сегодня закончилась (2 из 2). Новая — завтра в 00:00 или сразу с Pro.» и дальше перечень того, что даёт Pro;
  - баттлы — то же словами «Бесплатные баттлы на сегодня закончились (1 из 1). Новые — завтра в 00:00 [или сразу с Pro].»;
  - вид «только Pro» (`limit = 0`) — без «закончились», числа и времени: слова Pro (см. «Вид «только Pro»» выше);
  - причина `practice` (`PRACTICE_PLAN=pro`) и лид без цифр отказа — то же слово о практике: «…и баттлы с друзьями…» только там, где баттлы есть (`practiceAccess.battle`), при выключенных баттлах — `paywall.lead_practice_solo`.
  Слова: практика — не «тренировка» (так названы занятия по карточкам), баттл — не «вызов» (так названы недельные «Вызовы» друзей); в uz — `amaliyot` и `bellashuv`. В скобках `limit` дважды (не «3 из 2», если лимит понизили). Время — в поясе ученика, как дата на «Сегодня» (`today.data.timezone`; без него — пояс устройства): «завтра в 00:00», если момент сброса — начало следующих суток ученика (так сервер присылает всегда; `calendarDay` из `format.ts`), иначе только время («в 19:00») — часы устройства могут быть сбиты, а день они подтвердить не вправе. Остальное — как у других причин: заголовок, что даёт Free, покупка или `coming_soon`, промокод, «Повторить слова». Список `ProBenefits` получил пункт про практику (второй, после новых слов), он виден в листе и на экране «Подписка». Какой именно пункт — **слово сервера**: `practice.pro_promise` в `/me` (`both` → `benefits.practice` «Практика и баттлы без дневного лимита», `solo` → `benefits.practice_solo` «Практика без дневного лимита», `none` — строки нет). Правило одно, на сервере (`ProPromises`; его же читают лендинг и счёт Stars, `docs/18` §3, `docs/04` A.2): практика читающему не открыта (`PRACTICE_ACCESS=off`, ученик вне пилота, старый сервер без блока `practice`) — `none`; при `PRACTICE_PLAN=pro` практика целиком в Pro — `both`, при выключенных баттлах (`PRACTICE_BATTLE=false`) `solo`: баттлы, которых нет, не продаются; иначе строка есть, пока у Free есть дневной лимит, который снимает Pro (баттлы включены и у Free есть лимит баттлов — `both`; есть лимит сессий — `solo`; оба пусты — `none`: снимать нечего). `ProBenefits` ничего не выводит из `available` / `battle` и лимитов; пока `/me` не пришёл — `none`, строки нет.

## 5b. «Караван» — игра (docs/18 §12.9)

> Статус: G2.7a — карта и забег (в работе: 5b.1–5b.2 — задача «карта», 5b.3 — задача «забег»). Экраны босса, каравана дня, «моего каравана» и каравана класса — G2.7b, G2.7c, G2.9b. Контракт API — `docs/04` A.18, поведение — `docs/18` §12.9. Пока `GAME_ACCESS=off`, `me.game.available = false` и входов в игру нет.

### 5b.1 Общее: маршруты, сторы, входы, ошибки, пейвол

**Маршруты** (`router/index.ts`). `/game` (имя `game`, вкладка «Курсы»; `?course=<slug>` — курс, иначе активный курс ученика; `?stop=<lesson_id>` — открыть лист этой стоянки сразу после загрузки карты). `/game/runs/:id` (`game-run`, без таб-бара) — §5b.3. Экран босса, «Караван дня», «Мой караван» и класс — G2.7b/c, G2.9b.

**Сторы.** `game` — карта (`map`, `status`: `idle | loading | ready | unavailable | error`, `error`) и старт стоянки: `startStop(lessonId, replaceActive?)` → `{ id }` или типизированная ошибка (`{ error: { code, kind, details, message } }`); курс берётся из загруженной карты. Единственные запросы стора — `GET /game/map` и `POST /game/runs`. `me.game` (`available`, `limits`, `pro_promise`, `coins`, `tickets`) живёт в **billing-сторе** вместе с остальным `/me` (`billing.game`, геттер `gameAccess`; пока `/me` не пришёл — «игры нет»). Ни `game`, ни экран карты **не запрашивают `/me`**: на «Сегодня» Pro-ученик `/me` намеренно не читает (стережёт `TodayView.spec.ts`). Лимиты, которые приносят сами ответы игры (`limits` карты), записываются в billing-стор как самое новое слово (`setGameLimits`), как у практики.

**Входы.** Карточка «Караван» — только там, где `/me` уже загружен, и только при `me.game.available`: кнопка курса (`CourseView`, под «Практикой») → `/game?course=<slug>`. Пока `/me` не пришёл — входа нет. Вход на «Сегодня» появится с `/today.game` (G2.3 / G2.7b).

**Коды ошибок** (`KNOWN_ERROR_CODES` + `error.code.*` ru/uz): `game_unavailable`, `game_limit_reached`, `game_pro_required`, `game_run_active`, `game_daily_done`, `boss_not_ready`, `stop_locked`, `game_not_enough_material`, `stage_not_found`, `stage_not_in_course` (`course_not_found`, `lesson_not_found`, `lesson_not_in_course` уже есть у практики). Контекст сообщений — `game` (`error.closed.game`, `error.forbidden.game`). Коды забега (`game_run_not_found`, `game_run_closed`, подсказки, бустеры, лавка) — §5b.3 и следующие задачи.

**Пейвол `PaywallReason = 'game'`.** Забег по карте у Free ограничен (docs/18 §3): бесплатный забег в день и билеты (за серию и за друзей); Pro — без ограничений. Лид (один для отказа по лимиту и для босса Pro): «Караван: бесплатный забег в день и билеты за серию и за друзей. В Pro — без ограничений.» Чисел в тексте нет: они приходят только в `me.game.limits` (до G2.8 это `null`) и показываются строкой на листе стоянки, не в пейволе. Остальное — как у других причин: что даёт Free, покупка или `coming_soon`, промокод, «Повторить слова».

### 5b.2 Карта `/game`

Контракт — `docs/04` A.18 (`GET /game/map`), поведение — `docs/18` §12.9. Экран — `views/GameMapView.vue`, тесты — `views/__tests__/GameMapView.spec.ts`.

**Курс.** `?course=` → иначе активный курс из `today.data.active_course` (если «Сегодня» ещё не читалось — `today.load()`, это `/today`, не `/me`). Курса нет — состояние `no_course` («Выберите курс», кнопка в «Курсы»). Telegram Back → «Сегодня».

**Состояния.** `loading` · `ready` · `empty` (ни одна стоянка не открыта: «Начните урок в карточках — откроется первая стоянка», кнопка «Учить» → курс) · `unavailable` (403 `game_unavailable`: «Караван пока недоступен») · `error` («Повторить»; в том числе 404 `course_not_found`). Баннер `active_run` («Идёт забег: 3 из 9 · Продолжить» → `/game/runs/<id>`) стоит над дорогой в `ready` и `empty`.

**Дорога.** Вертикальный список городов в порядке модулей. Город: имя Шёлкового пути (`city`) и название модуля (`title`; пусто → «Модуль N»); метки друзей у города (`friends` с `city_number` = номер города; имена, не больше 3, остальные «+N»). Стоянки — точки со звёздами 0–3 (звезда 12 px, один столбец на 320 px, цель нажатия ≥ 44 px), подпись «Стоянка N» + название урока. Закрытая (`unlocked: false`) серая, с подписью «начните урок», не нажимается; город без открытых стоянок приглушён.

**Босс** — неинтерактивный чип у города (старта босса нет: экран — G2.7b): `ready` «Босс ждёт», `not_ready` «ещё N стоянок» (`required_stops - cleared_stops`; если стоянок хватает, но слов не хватает — «ещё N слов»), `defeated` «Босс побеждён», `locked_by_plan` — чип Pro, нажатие → `PaywallSheet reason="game"`.

**Лист стоянки** (`BottomSheet`): «Стоянка N · <урок>», «8–10 заданий, 3 фляги», звёзды и лучший счёт, если уже играли; строка лимитов Free — только если `limits.runs` не `null`: «Сегодня бесплатно: 1 из 1 · билеты: 2» (при `limits = null` строки нет — чисел не выдумываем); кнопка «В путь» → `startStop`. Лимиты: `limits` карты, иначе `me.game.limits`.

**Старт и ошибки.** 201 → `router.push('/game/runs/' + id)`. 403 `game_limit_reached` и `game_pro_required` → `PaywallSheet reason="game"`; 409 `game_run_active {run_id, kind, progress}` → лист «Идёт забег: продолжить / начать этот (прежний не засчитается)», «начать этот» → тот же старт с `replace_active: true`; 409 `stop_locked` → тост и перечитывание карты; 422 `game_not_enough_material` → лист «Слов пока мало для этой стоянки» с кнопкой «Учить»; 403 `game_unavailable` → `unavailable`; прочее — тост по `errorMessage`. Пока идёт старт, второе нажатие игнорируется; ответ, пришедший после ухода с экрана, никуда не уводит.

**`?stop=<lesson_id>`** — адрес кнопки «Ещё раз» итога забега: после загрузки карты открывается лист этой стоянки (если она есть и открыта; иначе параметр молча игнорируется). Закрытие листа убирает `stop` из адреса (`router.replace`).

**Не входит:** «Караван дня», старт босса, класс (G2.7b / G2.9b); `daily` и `class_caravan` из ответа карты экран не читает.

### 5b.3 Забег `/game/runs/:id` и итог

_(G2.7a, задача «забег»; контракт — `docs/18` §12.8–§12.9, `docs/04` A.18 «Забег»)_

**Маршрут** `game-run` (`/game/runs/:id(\d+)`, без таб-бара). Карта открывает его после старта; в query можно передать `course=<slug>` и `stop=<lesson_id>` — `GET /game/runs/{id}` не отдаёт ни slug курса, ни id урока, а «Ещё раз» и «На карту» ведут на `/game?course=<slug>&stop=<lesson_id>` и `/game?course=<slug>`. Без query (ссылка напрямую) обе кнопки ведут на `/game` (активный курс).

**Файлы.** `api/gameRunTypes.ts` (типы), `api.gameRuns.{get, answer, hint, abandon, audioBlob}`, стор `stores/gameRun.ts`, экран `views/GameRunView.vue`, `components/game/`: `ChoiceTask`, `SpellTask`, `GapTask` (виды из слова), `PracticeTask` (адаптер к компонентам практики), `GameReveal` (разбор видов из слова), `RunHeader`, `FlaskIcons`, `EventBanner`, `RunSummary`.

**Стор `gameRun`** (по образцу `practice`): `status` — `idle · loading · event · playing · submitting · reveal · summary · closed · error`.
- Поколения: `generation` растёт с каждым забегом, ответ прежнего забега отбрасывается. Пока статус не `playing`, повторное нажатие ничего не шлёт.
- `request_id`: один на задание (пара — на каждую попытку «left|right»). При сетевой ошибке / 5xx / 429 id и **сам ответ** сохраняются (`pendingRequestId`, `pendingAnswer`), экран остаётся на задании с тостом, повтор уходит тем же id и тем же ответом. Подсказка — свой id (`pendingHint`).
- `element_not_current` / `unknown_element_id` → тост «Задание уже сменилось» и перечитанный `GET`; `pair_already_matched` → тихий перечит; `answer_already_accepted {verdict}` → перечит и разбор «ответ засчитан раньше» (только вердикт); прочие 409/422 (`invalid_answer_shape`, `unknown_option_id`, `request_id_reused`) → тост, задание пересоздаётся.
- 410 (`game_run_closed {finish_reason}`) → `closed`. Забег, прочитанный как `finished/abandoned|expired`, — тоже `closed`; `completed|failed` — `summary`.
- Событие элемента (`current.event`): состояние `event` — баннер «Песчаная буря» / «Оазис» / «Базар» ~1,5 с (экран, не стор, ставит таймер и зовёт `dismissEvent`), показывается один раз на элемент; затем задание. Результат ответа `event_applied = oasis` показывается в разборе («Оазис: фляга вернулась»).
- Подсказка базара: кнопка «Подсказка за N» только пока `hint.available` (сервер: событие `bazaar`, вид с подсказкой, ещё не куплена); после покупки задание остаётся (введённое не теряется), на нём появляется `hint` — убранные варианты (`options_removed`) или первые буквы (`prefix`). Баланс монет сервер присылает только в ответе подсказки и в `details` `coins_insufficient`; до этого рядом с ценой баланса нет. `coins_insufficient` → тост; `hint_not_available` → перечит, кнопки нет.
- Разбор (`reveal`): вердикт символом и словами + разбор вида + «Дальше»; на последнем — «К итогу». Раунд пар идёт в `playing` до `round_done`; если забег кончился на ошибке в раунде — разбор.

**Экран.** Шапка: ✕ (цель 44 px), «3 / 10» (в разборе — номер отвеченного), полоса, фляги (`FlaskIcons`: `flasks` из `flasks_max`, с подписью для чтения с экрана), счёт, метка комбо «×N» с третьего подряд. Выход: ✕ и Telegram Back → лист «Выйти? Забег не засчитается» → `abandon` → карта; в `summary`/`closed` ✕ ведёт на карту без вопроса. Бустеры: ряд не рисуется, пока `boosters.available` пуст (G2.5b). Аудио `listen`/`dictation` — `usePracticeAudio` (blob с заголовком авторизации), «Слушать» воспроизводит с начала, повтор — той же кнопкой.

## 7. TTS (useTts)

> Порядок (задача 1.2c): `speak(text, lang, audioUrl)` — если у карточки есть `audio_url`, играет предгенерированный mp3; при `null` или ошибке воспроизведения — Web Speech API, затем `GET /api/twa/tts`. Пример ниже — исходная схема без `audioUrl`.

```ts
// src/composables/useTts.ts
export function useTts() {
  const synth = window.speechSynthesis
  const supported = !!synth
  let voice: SpeechSynthesisVoice | null = null

  function pickEnglishVoice() {
    if (!synth) return null
    const voices = synth.getVoices()
    return voices.find(v => v.lang.startsWith('en')) || voices[0] || null
  }

  async function speak(text: string) {
    if (!supported) return speakFallback(text)
    voice ??= pickEnglishVoice()
    const u = new SpeechSynthesisUtterance(text)
    u.lang = 'en-US'
    u.rate = 0.9
    if (voice) u.voice = voice
    synth.cancel()
    synth.speak(u)
  }

  async function speakFallback(text: string) {
    const url = `/api/twa/tts?word=${encodeURIComponent(text)}`
    const audio = new Audio(url)
    await audio.play()
  }

  return { supported, speak }
}
```

Детали:
- На iOS Safari `synth.getVoices()` возвращает пустой массив при первом вызове — нужно дождаться события `voiceschanged`.
- На Telegram Desktop (Windows/macOS) Web Speech API обычно работает стабильно.

## 8. Интеграция с Telegram UI

- `WebApp.MainButton` — не используем (UX хуже, чем свои кнопки, в рамках карточек).
- **Тема.** `composables/telegramTheme.ts` (`initTelegramTheme()` в `main.ts`) копирует **все** параметры `WebApp.themeParams`, которые нужны дизайну, в CSS-переменные на `<html>`; соответствие «параметр → переменная → фолбэк» — docs/14 §4.1 (14 параметров: `bg_color`, `text_color`, `hint_color`, `link_color`, `button_color`, `button_text_color`, `secondary_bg_color`, `section_bg_color`, `accent_text_color`, `destructive_text_color`, `subtitle_text_color`, `section_header_text_color`, `section_separator_color`, `bottom_bar_bg_color`). Параметр, которого клиент не прислал, **удаляется** (`removeProperty`) — срабатывает фолбэк из `style.css`. Компоненты используют только семантические токены `--app-*` (`page`, `surface`, `fill`, `accent`, …), а не `--tg-*` напрямую:
  ```css
  :root { --tg-bg: #fff; --app-page: var(--tg-secondary-bg); /* … */ }
  ```
- **Смена темы на лету.** Подписка `WebApp.onEvent('themeChanged', …)` применяет тему заново; `document.documentElement.dataset.theme = WebApp.colorScheme` (`light`/`dark`) — для `color-scheme` нативных контролов.
- **Цвет шапки и фона окна.** При `WebApp.isVersionAtLeast('6.1')` вызываются `setHeaderColor('secondary_bg_color')` и `setBackgroundColor('secondary_bg_color')` — шапка Telegram сливается с фоном страницы. Всё в `try/catch`: вне Telegram — no-op.
- **Кнопка «Назад»** (`composables/useBackButton.ts`, правило — docs/14 §5.3): `useBackButton(target)` вызывается в `setup()` экрана; `target` — место назначения (`{ name: 'courses' }`), функция или `null`. Корни вкладок (`today`, `courses`, `decks`, `league`, `friends`, `profile`) — `null`: кнопка скрыта. Внутренние экраны ведут на корень своей вкладки (`course → courses`, `deck → decks`, `settings|billing|achievements|referrals → profile`). Тренировка личной сессии (`lesson`, `daily_review`) возвращает на `/today`, групповая (`group_lesson`) закрывает Mini App; экзамен — закрытие. Практика (§5a): `practice-hub → course` (курс хаба), `practice-session` → хаб сессии (шаг назад по истории, если предыдущая запись — этот хаб, иначе `replace`; подтверждения нет, ответы уже сохранены; пока о сессии ничего не известно — `courses`), `battle-new → friends`, `battle` — через лист `LeaveConfirm` (§5a.5). Текстовых ссылок «← К курсам» нет. Если предыдущая запись истории и есть цель, переход идёт через `router.back()` (экран возвращается на ту прокрутку, на которой его оставили; история не растёт), иначе — через `router.push`. Обработчик снимается при уходе с экрана. Все экраны с системной «Назад» используют `useBackButton`; `showBackButton` из `useTelegram` вызывается только внутри него.
- **Хаптик** (`useTelegram()`): `impactOccurred('medium')` — оценка карточки (кнопки флеш-карты, выбор варианта, «Проверить» у набранного ответа, ответ на вопрос экзамена); `impactOccurred('light')` — «Показать перевод», «Дальше» (после вердикта и после неверного варианта) и мелкие действия экранов (поделиться, скопировать, вызов друга); `notificationOccurred('success' | 'error')` — верный / неверный вариант в «4 вариантах», ответ экзамена, итог занятия и итоги экзамена; в практике — `impactOccurred('medium')` на ответ и `notificationOccurred('success' | 'warning' | 'error')` на вердикт (опечатка — `warning`; у пар — на конец раунда, неверное сопоставление — `error`); `selectionChanged()` — смена вкладки и кнопка озвучки.

## 8a. Локализация (i18n)

Языки интерфейса — **русский (по умолчанию) и узбекский (латиница)**; изучаемый язык (английский) не переводится. Внешняя библиотека (vue-i18n) не используется — модуль `src/i18n/` (~100 строк).

- **Выбор языка:** `Telegram.WebApp.initDataUnsafe.user.language_code` (через `useTelegram().languageCode()`) → `uz*` → `uz`, всё остальное (и запуск вне Telegram) → `ru`. Выбирается один раз в `main.ts` (`initLocale`), там же выставляется `<html lang>`.
- **Словари:** `ru.ts` — эталон; тип `Translations` выводится из него, поэтому `uz.ts` с пропущенным/лишним ключом не проходит `vue-tsc`. Ключи плоские, `section.name`. Plural-значения — объект форм `{ one, few, many, other }`.
- **API:** `t(key, params?)` — подстановка `{name}`; `tn(key, count, params?)` — форма по `Intl.PluralRules` (ru: one/few/many, uz: one/other; `{count}` подставляется автоматически); `useI18n()` в компонентах.
- **Ошибки API:** клиент не показывает `error.message` сервера (он английский), а локализует по `error.code` (`src/i18n/errors.ts`, список `KNOWN_ERROR_CODES`; остальное — по `kind` ответа: сеть, 403, 410, 429, 5xx). Новый код ошибки в бэкенде = новая запись в `KNOWN_ERROR_CODES` + строки `error.code.<code>` в обоих словарях.
- **Правила:** в `.vue`/`.ts` вне `src/i18n` кириллицы быть не должно (проверяет vitest). Новый текст = ключ в `ru.ts` и `uz.ts` одновременно.
